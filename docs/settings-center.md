# 设置中心

Web 的聊天抽屉保留构图、声音和麦克风快捷设置，完整配置集中到 `/settings`。原来的 `/settings/channels` 和 `/settings/agent` 继续有效，其余分类也可以直接打开或刷新。

| 导航分组   | 内容                                                                            |
| ---------- | ------------------------------------------------------------------------------- |
| 聊天       | QQ/微信连接、交流权限、自由交流、群路由、回复样式和发送节奏；桌面另有桌宠和陪伴 |
| 模型与声音 | 聊天、行为决策/Jev、记忆和向量模型；TTS 与 Realtime                             |
| 能力与任务 | 工具授权、后台任务、文件、候选开发审批、Skills/插件与 MCP                       |
| 记忆与资料 | 记忆建议、事实修正、来源与遗忘；照片/表情仍在对应渠道内管理                     |
| 日程       | 日历、提醒、计划任务和设备回执                                                  |
| 连接与设备 | Runtime、参与者和运行诊断；桌面另有本地数据清理和 Worker Pack                   |

`SettingsShell` 统一分类搜索、连接状态、桌面/窄屏导航、内容滚动与视觉层级。搜索匹配功能关键词，例如“打字”“自由交流”“Jev”。每个产品保留自己的分类注册表，Web 构建不导入桌宠和桌面专属设置模块。共用的模型、声音、MCP 和日历表单已移到产品无关目录，原导出路径保留兼容入口。Google 首次授权/权限升级、原生模型包和设备接入继续由桌面处理。

Apple Liquid Glass 视觉层使用系统字体、连接页同款暗紫底色（#231b29 → #151119）、灰紫玻璃表面和低饱和梅紫主按钮。悬浮侧栏、页头和分段导航采用玻璃材质，内容卡片保持高不透明度；页头和正文共享最大 1040px 容器，渠道页不再保留独立的 820px 宽度。页面固定在视口内，正文独立滚动；桌面外边距为 20px，页头与正文之间保留至少 32px 间距，窄屏至少 24px。正文和表单标签以 14px 为主，按钮和输入框至少 40px，触屏主要控件至少 44px。窄屏改用顶部分类导航，表单和 Skills 主从布局改为单列。减少动态效果、增加对比度、减少透明度以及不支持背景模糊的环境都有对应样式；不使用 WebGL 折射或新增渲染依赖。

侧栏使用固定图标列与文字列，不再随标签长短居中偏移。连接页与设置页通过 `plum-theme.css` 共用调色板；参与者、权限确认、数据清理、引导及文档预览等独立弹窗显式接入主题。旧组件保留非主题消费者的原色回退，主题内使用共享语义色。

TTS Provider 表单由共享组件直接加载共享样式，避免 Web 缺少桌面专属 CSS 时出现原生按钮或标签挤贴输入框。字段使用统一网格，保存区支持换行，未命名按钮也有完整的公共样式；梅紫主要操作在悬停时保持足够的文字对比度，文字强调色与按钮填色分别定义。

“扩展与 MCP”直接提供 Skills、插件、MCP 三个标签。Skills 支持本地目录搜索，当前能力的参数和执行按钮位于详情中；最近运行、空目录、无匹配、加载和错误均有明确反馈。插件保留本地安装、测试插件、启停、卸载和隔离状态；MCP 保留连接编辑、测试、能力检查及资源/Prompt 读取。聊天快捷入口通过 `presentation: "embedded" | "dialog"` 复用管理内容。`SettingsDialog` 显式接入主题和公共控件，管理背景 inert、Tab 焦点循环、Esc 关闭及入口焦点返回，记忆中心也使用该容器。

模型配置按用途切换，角色状态和输入预算放在高级折叠区；QQ 行为集中到“交流与权限”，短期群上下文预算仍在折叠区。表单继续使用各自的保存动作、完整策略校验、版本校验和明确的错误回读，不因导航而扩大权限。

设置分类第一次访问后才挂载；同一 Runtime/参与者内切换分类保留草稿和滚动位置。模型用途切换也保留每个角色的草稿。修改、保存中和已保存状态可见。Runtime 身份变化时页面重建，防止旧范围的草稿被带入新连接。设置页沿用 `useSettingsRuntime`，不建立消息事件流、麦克风或播放链路。关闭/刷新页面仍会丢弃未保存修改；渠道内切换 QQ/微信/交流权限维持原有面板生命周期。

能力分页发现与已保存的任务/文件并行读取，避免刷新后任务列表等待整个能力目录。两个读取路径都保留 Runtime 身份和请求版本校验，过期结果不能覆盖当前页面。

分类组件可接收 `active`。隐藏的 Skills、任务、索引进度和日程面板停止自己的轮询；共用 Runtime 连接健康检查仍由设置页面持有。页内切换保留 Skill 参数、插件路径、MCP 名称/传输等普通草稿；离开 MCP 面板清理未保存的 Bearer Token、Prompt 参数和读取结果。读取版本随选中连接和生命周期递增，旧资源结果不能重新出现。第一次加载 MCP 时禁用编辑，返回页面后读取目录不会覆盖既有草稿。切换 Runtime/参与者继续重建整个设置范围；保存动作、CAS、权限确认和后端协议保持原有行为。

扩展页和能力页只在各自可见时拥有权限确认入口，防止已访问的隐藏分类产生重复弹窗或继续轮询。聊天快捷弹窗遇到上层 Runtime 确认时让出键盘控制，拒绝操作后恢复快捷弹窗焦点。

隔离浏览器验证：

```bash
PYTHONPATH=services/runtime/src:packages/protocol-python/src:packages/model-worker-sdk-python/src \
  .venv/bin/python tools/agent/browser_fixture_runtime.py --root /tmp/cw-settings-browser --port 8778
VITE_RUNTIME_URL=http://127.0.0.1:8778 VITE_RUNTIME_TOKEN=disposable-agent-browser-fixture \
  pnpm --filter @chatwaifu/web exec playwright test --config playwright.settings.config.ts
```

验证使用一次性 Runtime，覆盖 Web/桌面 1280px 与 390px 布局、功能搜索、模型用途、跨分类草稿保留、全部分类入口、页面无横向溢出和无额外媒体链路。构建产品隔离检查继续分别运行。双产品开发服务器使用独立 Vite 依赖缓存，避免互相失效。

Liquid Glass 的 Chromium/WebKit 完整矩阵：

```bash
VITE_RUNTIME_URL=http://127.0.0.1:8778 VITE_RUNTIME_TOKEN=disposable-agent-browser-fixture \
  pnpm --filter @chatwaifu/web exec playwright test --config playwright.glass.config.ts
```

该配置覆盖两种产品、1870×864、1548×864、1280×900、1024×768、390×844、1280×480 以及 200% 缩放对应的 640×450 CSS 视口重排。包括 QQ/微信/权限和 Skills/插件/MCP 子页、末项和保存按钮可达、键盘焦点、触屏尺寸、离线恢复、长文本和透明度降级。QQ 已绑定分支使用浏览器合成数据，不连接真实账号；缩放检查验证等价视口重排，未操作原生浏览器缩放菜单。详细验证范围和发布状态见 [Liquid Glass 验收记录](./settings-liquid-glass-validation.md)。
