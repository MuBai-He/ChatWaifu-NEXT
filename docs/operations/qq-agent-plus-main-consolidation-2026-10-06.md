## Squash 合入与后续基线

仓库只允许 squash。PR 00 的 base 为 main，后续 PR 的 base 为前一项分支，因此查看每个 PR 时仅显示本项增量。按顺序合入，每项须通过它当次触发的 CI 和审阅。服务器部署使用完整系列合入并验证后的版本。

每合入一项后：

1. 获取新的远程 main，记录已合入 PR 的来源 head 和 squash 后的 main SHA。
2. 将下一项的独有提交重放到新 main；后续分支依次重放到更新后的前置分支。使用已记录的旧前置 SHA 限定重放范围，避免把旧提交重复带入。
3. 核对每项差异及最终累计文件树。仅更新本系列的新分支，并使用指定旧远程 SHA 的 `--force-with-lease`；保留所有原开发分支。
4. 将下一项 PR 的 base 改为 main，等待它更新后的 CI，再继续。

Squash 后旧来源 SHA 通常不是 main 的祖先；不能据此判断代码遗漏。若 main 同时有其他修改，检查实际差异并整合，不能用完整来源快照覆盖那些修改。
