# 提醒离线边界验收

2026-09-29 在现有 HTTPS Runtime 上，使用三个独立配对的临时设备和三个一次性闹钟验收服务器投递：

- 到期后约 20 秒重连：仅目标设备收到一次投递，原定时间正确；关闭后不进入未处理记录。
- 已展示但不点击：两分钟有效期结束后成为 `unhandled`。
- 一直离线直到两分钟有效期结束：成为 `missed`，随后上线不补发投递。

通过主人接口核对历史状态，随后取消三条临时任务、清除两条历史记录、撤销三个临时设备；只读数据库核对活跃测试设备为零、任务均已取消、历史记录均已清除。现有仓储边界检查和桌宠投递组件检查通过。

验收发现普通提醒贪睡后原本误用闹钟的两分钟迟到窗口。修复后，闹钟仍为两分钟，普通提醒保留一小时；仓储回归检查覆盖该差异。

隔离设备 API 验收不等于 macOS 原生通知或声音验收。用户已确认过首次提醒、五分钟贪睡与重启恢复。后续代码审查发现断网点击关闭／贪睡原先只停本地声音，重启窗口会丢失操作；配对撤销还会导致无意义的 403 重试。修复后选择先持久写入原生设备记录，恢复连接时幂等提交；已展示的过期投递可以补交关闭，但过期贪睡明确报未生效，不补响。配对撤销暂停该设备的服务端轮询，等待重新配对。针对性服务器、React 与 Rust 检查覆盖这些状态和原生记录序列化；仍未把测试替代为真实 macOS 通知横幅、物理扬声器或睡眠唤醒验收。外部来源的未知写入结果不在本次范围。
