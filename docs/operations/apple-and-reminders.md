# Apple 日历、提醒事项与持久闹钟验收

这部分代码需要同时更新 Runtime 和桌面宿主，旧版客户端没有 EventKit 命令。
本轮没有替用户授权、改动真实日历、部署生产服务器或启动实际闹钟。

## 启动准备

1. 更新服务端源码，保留独立的 state/config/data 和凭据文件，备份 SQLite 后启动 Runtime。
   设置 `[personal_assistant] enabled = true`。Google OAuth 是否配置不影响任务调度。
   SQLite 自动应用迁移 34。不要将迁移后的数据库交给旧版 Runtime。
2. 在本分支运行 `pnpm install --frozen-lockfile`，随后
   `pnpm --filter @chatwaifu/desktop dev`。原生 EventKit 需要 macOS 14+ 和 Xcode 命令行工具。
   正式使用应验收带完整 Info.plist 的 `.app`；开发宿主的系统授权可能需要重新确认。
3. 使用已有的 HTTPS 服务地址和访问令牌连接。任务设备能力不经普通 LAN HTTP 传输；
   本机直连开发需显式设置 `device_allow_direct_loopback = true`；带代理头的请求仍拒绝。
   该选项仅供没有反向代理的本机 Runtime，默认关闭。服务器端不要启用任意代理头解析。

## 你醒来后的实机步骤

1. 设置 → 个人助理 → 提醒事项与定时任务 → 配对此设备。保持桌宠窗口运行，确认设备在线。
2. 点击“允许系统通知”，再分别点击 Apple 日历和提醒事项授权按钮。
   在 macOS 系统弹窗中自行允许；拒绝过则到系统设置 → 隐私与安全性重新开启。
3. 仅勾选一个测试日历和测试提醒列表。先读取，确认能看到现有条目。
4. 新建一个不重要的测试事项，等待“设备已完成”，到 Apple 应用核对标题与日期。
   重新读取后编辑、完成提醒事项、删除测试条目；跨设备 iCloud 同步需单独观察。
5. 创建两分钟后的闹钟。验证桌宠卡片、提示音、关闭、五分钟贪睡。
6. 新建任务后重启 Runtime：任务仍在。取消任务：不再响铃。
   关闭桌宠超过到期两分钟再打开：旧闹钟不能突然补响。
7. 撤销设备：它不能读取／执行新的 Apple 操作，发给它的任务取消。
8. 文本对话中先查询任务／Apple 列表，按权限提示授权；创建和删除等写操作走现有确认框。
   “排队中”不算成功。操作结果不确定时先看 Apple 应用，不要重复创建。

## 当前边界

- 普通日历事件和提醒事项基础字段可用；复杂重复、邀请、全天事件等编辑请用 Apple 应用。
- 闹钟依靠在线桌宠，不能唤醒关机设备，也不控制 iPhone 的时钟闹钟。
- Google 日历读取沿用已验收功能；Google 写入、云端原生语音写工具和 HA 接入不在本轮交付内。
- 权限、iCloud 同步、系统通知音量、真实睡眠恢复、Linux 桌面声音均需实机验收。
