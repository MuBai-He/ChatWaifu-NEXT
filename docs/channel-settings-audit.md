## 结论与页面层级

原版本有后端功能缺少 UI、微信旧绑定状态不准确、Web 无渠道页等缺口。本次补齐并共享：

1. **微信**：连接状态与绑定 → 消息开关、表情发送 → 回复样式 → 身份详情 → 私聊表情/微信照片。
2. **QQ**：NapCat 配对与连接 → 回复样式、私聊表情 → 主动文字问候 → 群成员和回复权限。
3. **权限与预算**：QQ 主人私聊能力、原生收藏 → 群旁听缓存、限流及按需摘要预算。

基本开关直接显示；节奏参数、绑定身份、记录与预算用分组/折叠展开。统一字段、按钮、开关、
错误/加载/离线状态与键盘焦点。Web 和桌宠复用同一组渠道组件；设置页不拥有本机音频播放。

## 默认阈值与生效方式

新 policy 的 QQ 私聊语音输入、语音回复、原生收藏默认允许沿用原行为；公网读取从
`public_web.qq_owner_reads_enabled` 初始化。是否实际使用还受绑定、服务是否配置及该功能原有 opt-in 限制。
群语音仍逐群默认关闭，不与私聊开关联动。

| 群旁听设置                     |                默认值 | UI/协议边界                              |
| ------------------------------ | --------------------: | ---------------------------------------- |
| 最多缓存群数                   |                    32 | 1–128                                    |
| 单条字符 / 整群条数 / 整群字符 |      800 / 96 / 24000 | 80–2000 / 32–512 / 3200–128000           |
| 保留时间                       |                900 秒 | 30–3600 秒                               |
| 每人条数 / 字符                |             24 / 6000 | 1–128 / 80–32000，不能大于整群容量       |
| 每人每窗口消息数 / 窗口        |             6 / 30 秒 | 1–30 / 1–300 秒                          |
| 重复文本窗口                   |                 60 秒 | 1–900 秒                                 |
| 旁听输入预算                   |       1536 参考 token | 128–8192；仍最多占模型可用输入的四分之一 |
| 摘要输入 / 输出                | 3072 / 256 参考 token | 256–16384 / 64–1024                      |
| 摘要超时                       |                  8 秒 | 0.1–30 秒                                |

每人实际容量还受“群容量 ÷ 受众人数”限制。参考 token 不等于供应商计数，扩大旁听预算不保证回答质量；
本次没有重新压缩提示或修改模型总输入/输出预算。保存旁听策略后旧缓存清空，进行中对话保留已冻结材料；
关闭语音权限仍会阻止未发布/未发送的私聊语音。关闭语音输入会取消在途预处理。

第一次 UI 保存前沿用 TOML/env；保存后 SQLite 的 revision/policy 是渠道权限与旁听预算的持久配置，
重启后优先于这些字段的 TOML 默认值。其他模型、服务 URL、凭据及部署参数继续由原配置负责。
保存使用 CAS；遇到冲突、超时或不确定响应会读回，操作不会自动重复执行。

## 本地启动与服务器版本

这份实现位于上述隔离工作区，主目录 `/Users/mubai/Desktop/CW2` 尚未合入，不能用旧主目录的启动结果验证新版。
在该工作区按已有开发方式启动：

```bash
cd /Users/mubai/.codex/worktrees/messaging-short-replies/CW2
make server
# 另一个终端：
pnpm dev:web
# 或者桌宠设置界面：
pnpm dev:desktop-ui
```

Web 打开 `/settings/channels`（也可从对话设置进入“消息渠道与权限设置”）；桌宠打开“设置 → 渠道”。
选择本地或远程 Runtime 并输入该后端访问令牌。NapCat 地址指向 **Runtime 所在机器**，不是浏览器机器；
QQ 要先在 NapCat 登录，再按 UI 的配对指令绑定主人。微信仍需在手机扫码确认，后端需可用的安全凭据库。

新“权限与预算”要求同版本后端和 schema 44。旧服务器缺少 `/v1/channels/settings` 时会明确提示更新，
不宣称设置已经生效。此次不部署到 `192.168.1.103`、不改生产配置、不发送 QQ/微信消息，
既有服务器和手机端验收不等同于本次页面源码验收。
