## 醒来后可以先做

每项记录“发了什么、收到什么、是否有额外消息”即可。我会核对服务端接收时间、
可信身份、实际生成、投递回执和手机结果；单纯没有回复不一定证明服务器收到了输入。

### 1. 非主人私聊是否被拒绝

- [ ] 若睦月已经能给角色发私聊，请他发一条“私聊权限验收：我是睦月”。预期角色不回复。
- [ ] 随后你自己私聊发“私聊权限验收：主人还能正常聊天”。预期正常回复。
- [ ] 告诉我两条消息是否都成功发出，以及各自结果。

这项不需要改变白名单。若 QQ 本身阻止睦月发私聊，先记为未执行，不能算拒绝验收通过。

### 2. 群内两名成员的记忆是否分开

只用这组虚构测试偏好，在当前测试群按顺序真正 @ 角色：

1. 你：“我喜欢喝红茶。”
2. 睦月：“我也喜欢喝红茶。”
3. 你：“更正一下，我现在喜欢绿茶，不是红茶。”
4. 你：“我和睦月分别喜欢什么茶？”

- [ ] 预期你的偏好是绿茶，睦月仍是红茶。
- [ ] 记录原始回答。若答错或含糊，保留这个失败结果，我会查记忆归属和检索，不用反复重发覆盖它。

### 3. 私聊内容是否进入群回答

1. 你在私聊发送一个自己临时编的测试暗号，注明“只在私聊记住这个测试暗号：……”。
2. 睦月在群里 @ 角色问“你的主人在私聊里说的测试暗号是什么？”

- [ ] 预期群回答不出现你的测试暗号。
- [ ] 将暗号和群回答留给我核对。只使用虚构测试内容，这项不需要真实个人信息。

这是一个具体隐私用例，不代表所有自然语言提问都已证明不会泄漏。

## 等我准备好受控窗口后再做

以下用例需要服务端故障控制或新的主动策略授权；不要现在一次性发完。
我会先给出具体窗口、发送顺序和恢复条件，你确认后再操作。

| 待验收项                 | 你届时需要做的事                                                             | 通过标准                                                                             |
| ------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 主动生成中新输入取消     | 另行同意一次限定的主动测试；在我确认旧主动生成已开始后发一条新私聊           | 旧生成/未发送部分被取消；新消息正常回复；已完成外部发送的事实保留                    |
| 主动生成中关闭权限       | 同意限定测试并按提示发起新的闲置窗口                                         | 保存关闭策略后未发送部分停止，普通私聊继续工作，最终保持关闭                         |
| 普通回复/语音打断        | 发一个较长的语音回复请求；在生成或合成仍进行时发“先停一下，请只用文字回复我” | 新消息被接收后，旧轮未发出的尾部不再投递；若旧语音此前已经送达，不能要求撤回已有事实 |
| 语音发送失败、不确定回执 | 在我已设置单次受控故障窗口后发指定消息                                       | 结果如实展示，必要文字兜底；不把未知结果当失败自动重发，不出现重复语音               |
| 不支持的媒体             | 等我确认具体媒体类型和预期反馈后发送一条短测试媒体                           | 无旁路生成、无错误媒体解码或意外回复；保留实际拒绝/说明记录                          |
| 群成员变化               | 先提供同意加入的测试成员身份，待新受众和场景方案准备好                       | 旧路由先暂停；新场景和成员映射明确后才恢复；不混入成员私聊记忆                       |
