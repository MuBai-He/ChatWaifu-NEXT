## 保留的失败与修复

- [v1.0 试测](pilot-model-summary.json)发现 QQ 接口元数据挤占搜索召回，任务中的 Runtime 工作区语境不清晰，以及 B15 的开放问题判据有歧义。补充双语能力描述、按技能分散首批结果与可信场景说明；B15 在 v1.1 明确为未获回答的开放问题，保留同一个判据。旧场景和失败试次没有删除。
- 初次 v1.1 任务有一个原生工具协议失败。随后发现增量激活会覆盖已经加载的工具；改为累积激活，明确 `replace` 才收窄，并对尚未执行的无效原生批次给两次纠正机会。
- [边界试测](edge-pilot-summary.json)暴露旧循环拦住无副作用重试、候选修复遗漏参数/测试契约错误。任务由执行日志判断能否重试；候选修复覆盖结构、参数与实际沙箱测试。
- [最终修复前任务回归](task-regression-before-final-repairs.summary.json)为 57/60：一次错误校验值被误判未知，两次提供方空响应。写入前校验失败现在返回明确无副作用错误；空响应有两次受限重试。[全新最终回归](task-final-model-summary.json)为 60/60。
- 最后检查发现同一写入的 JSON 参数键顺序变化可能绕过已成功执行的缓存。现对完整调用使用排序键的规范 JSON 摘要，新建执行网关后调换参数顺序仍复用原成功记录，实际副作用只执行一次。
- PPT 原始长段落跨页后，整段字符串比对会因续页标题失败。现在按工人的 320 字段落分段，依原始次序逐段验证，重复段落也必须逐次匹配，实际长材料渲染测试通过。
- 浏览器发现产物列表按旧 session 隐藏了同所有者的已生成文件，现按授权 scope 列出。最后改进能力分批展示、完整授权选项与新搜索请求版本，避免旧分页结果覆盖新搜索。最终目视检查还发现原生 PDF 插件在滚动容器内裁切正文、关闭按钮点击异常，单凭 iframe 可见曾漏检。预览现使用按需加载的 PDF.js 6.4.299 独立 Worker 和有界 Canvas，弹窗固定头部、可分页、关闭后恢复焦点；两产品真实截图可见中文正文与数字 42，[预览截图](agent-preview-web.png)。渲染完成状态才计入浏览器通过。浏览器冷启动等待使用有界断言；ESLint 排除浏览器生成目录，避免与测试清理发生扫描竞争。

## 当前边界与待验收

旧群默认 off，桌宠默认 legacy，候选开发默认关闭。影子模式只记录决策，不创建自主任务或写群记忆；正式启用按群配置。明确任务和自主任务的发送预算分开计量。

官方目录含 178 个未废弃 NapCat 4.18.33 接口；七个查询动作完成场景适配，再加受控资料读取。其他动作仍显示“需要适配”，目录发现不等于可绕过权限执行。OpenAPI 重导入与原声明/来源哈希语义相同。

文档工人支持源码 Runtime 的 Word/PPT；需要 Node、PptxGenJS、LibreOffice 和中文字体。冻结打包 Runtime、配对设备文件、OCR/扫描 PDF 尚需适配。第一版候选开发支持隔离的纯 JSON 转换 MCP 技能；网络依赖开发与 Runtime 核心补丁发布链路尚未实现，不能把生成一个候选包当作通用自主软件开发完成。

没有本次生产部署证据；**QQ 手机实际收件、文件能打开、Calendar 真实查询/冲突/写入/回读、完整 Q02 品质**仍待独立验收。任务完成、文件渲染完成、平台接受与用户收件分别报告，未知结果不伪装成功。
