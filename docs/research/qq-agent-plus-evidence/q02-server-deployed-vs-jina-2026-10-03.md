# Q02：服务器搜索链路修复与来源质量复核

2026-10-03，由主代理直接实现和审查，未使用 AGY。服务器为
`192.168.1.103`。生产 Runtime 明确配置 `searxng` + `crawl4ai`，端口分别为
18080 / 11235。Jina 仅用于隔离对照，没有切换生产 Provider。

## 已确认的问题与修复

- SearXNG 容器的系统 DNS 曾将 Yandex 解析为 Mihomo Fake-IP；已改为与
  Crawl4AI 一致的递归 DNS。CW2 公网 `web.read` 继续显式使用
  `dns_resolver=cloudflare`。修复 DNS 后仍观察到上游超时，不能仅凭 DNS 宣称解决。
- SearXNG 旧健康检查每 30 秒执行真实外部搜索，现改用 `/healthz`。
  Yandex 默认 3 秒超时改为试验性的 8 秒；容器健康只证明服务存活。
- 查询曾被提前收窄到 3C/召回，且新闻结果占满 5 条后会挤掉 Wh 规则来源。
  现在保留原查询，加最多两个受 CAAC 域范围约束的补充查询，交错合并结果。
- SearXNG 的 HTTP 200 响应可能携带 `unresponsive_engines`。无结果且有引擎错误时，
  Runtime 现在返回可重试的 `web_search_engine_error`，不会伪装成成功的空搜索。
- 评测器 1.17.0 已支持与服务器相同的 Crawl4AI Reader。新增查询收据最初遗漏
  输出 schema，导致 v2 的 `invalid_skill_output`；主代理主动中止该批，保留
  15 条结果。补齐 web.search 1.3.0 schema 后从全新目录重跑，没有混用失败批。

## v4 逐项质量判断

充电宝三次法规轮均读取 CAAC 的阈值页与 2025 更新信息，包含 3C/召回、
100/160Wh、航司批准和随身携带条件。三个最终清单保留这些主要条件，但仍需改进：

- 三次法规轮均未附实际来源链接；部分细则由模型背景补出，没有说明当前读取原文
  是否支持，不能以关键词出现判为充分来源核实。
- r0/r2 清单将 `>100Wh 且 ≤160Wh` 写成 `100Wh～160Wh（含）`，与前面的
  `≤100Wh` 分支重叠。r0 清单只写召回批次，没有明确保留召回型号。
- Raft r2 把心跳间隔插入规范时序关系式并写成必须满足；r0 对重置计时器的
  “合法 RPC”描述过宽。r1 使用工程示例但表述也应谨慎。
- 技术问题后的三次话题切换均转入番茄炒蛋，没有强行继续技术主题；旅行建议
  保留三类各三条及两个室内备选，未因短消息风格截断。

复核参照 [Raft 论文 §5.2/§5.6](https://raft.github.io/raft.pdf)、
[民航局境内航班公告](https://www.caac.gov.cn/PHONE/XWZX/MHYW/202506/t20250626_227805.html)
和 [民航局携带规定](https://www.caac.gov.cn/PHONE/XXGK_17/XXGK/TZTG/201511/t20151105_11173.html)。
来源审计的 `factual_correctness=not_assessed` 保留原意：提及覆盖不是法律或质量批准。

## 实际请求与同来源对照

恢复模板 v12 后，8 条合成场景产生 12 次实际 Provider 请求。捕获的是适配器
payload 构建结果，不包含认证请求头；45 次参考 token 估算构建已排除，不能将
全部 57 次构建称为 HTTP 请求。12 次请求的 generation、system、context、history
均与 Provider 轮次日志匹配。资料读取后的最终回答请求包含引用要求和 Reader
返回的正文，且仅有一条 system 消息；没有发现这一轮因多条 system 消息而丢失
引用要求的证据。此处不能验证代理服务在接收请求后是否再次转换消息。

这 8 条结果供应商 prompt/completion/reasoning/total 为
`77740/3482/5783/87005`，p50/p95 为 `6901/33311 ms`。原始 payload、逐轮
匹配和用量见同名证据目录的 `wire-capture/`；正文仍受 Reader 独立窗口限制。

进一步固定同一条最终回答请求的来源、历史和预算，轮换三组设置各重复 3 次：
保留工具 schema 与 auto、去掉工具 schema、去掉 schema 并附现有结束工具阶段策略。
9/9 均正常返回 stop，没有再次请求工具，但 9/9 均未附实际来源 URL，条件范围与
无来源推断问题仍在。因此未采用“关闭工具阶段即可改善回答”的修改。三组原始
