# Q02 必需工具调用的一次纠正

2026-10-01。可信时间批次保留了 Gemini 的初始 `tool_choice=required` 请求未返回调用的失败。随后同端点的简单函数、原样来源 schema 与不透明工具名探测均实际返回正确调用；这些窄探测排除了“该端点总是无法调用这些工具”的说法，但没有确定完整角色请求忽略调用的全部原因。

本切片使用既有 AgentTurnOrchestrator：仅在初始必需工具回合正常以 `stop` 完成、没有调用且没有工具交换时，补一次明确的函数调用纠正。纠正保留原始用户输入、角色、时间、工具 schema、generation ID；只列当前已投影函数名，不提供法规答案、来源 URL 或新权限。首次未查证文本不回灌模型历史，也不进入用户输出。成功产生调用后移除临时纠正指令，后续读取、最终回答和写后禁用工具沿用原路径。

仍未返回调用时如实回退；不为工具不支持、错误、无终态、截断或过滤重试。每次 Provider 派发前检查当前 generation，父取消传播。初始纠正不执行工具，不计入四次实际工具调用配额；正常工具结果仍由 Registry → PermissionBroker → Executor 返回，权限撤销立即生效，写操作不重复。

每轮 Provider 理论上限由五轮调整为六轮（一次纠正 + 四次工具 + 最终回答），来自 Agent 常量；评估器 1.4.1 使用该值，并仍按开始日志计实际请求、保留被丢弃首轮 usage 和失败尝试。HTTP 内部重试与美元账单另算，未知 usage 不补零。版本与实现指纹拒绝混跑旧证据；所有新增真实评测使用新目录。

设计范围是初始缺失调用的有界修复及其评测记录。没有修改角色默认版本、Router 选择、工具 schema、权限策略、数据库或公开协议。来源时效、完整性和技术正确性仍独立验收，不能把函数调用成功当作 Q02 通过。

## 失败回归

旧实现的三个新回归失败：正常结束却缺调用直接回退、无法修复后执行真实 gateway、无法进入可取消的纠正轮次。新增检查还覆盖重复缺调用停止、非正常终态不补发、明确不支持仅一轮、四次工具配额、过期 generation 和写后禁用。

隔离 Runtime 的允许/拒绝测试同时覆盖纠正路径：读操作允许时真实 HTTP 一次、拒绝时零 HTTP，均没有持久 permission grant；首轮加后续真实 usage 全部计入，重启后调用配额不能重置。后续软件检查与真实模型结果在本文件追加，Q02 保持未通过。

## 工具阶段关闭与 1.4.2 复测

工具额度耗尽或尝试写操作后，最终请求现在明确工具阶段已经关闭，要求立即回答原始问题、区分成功和失败、说明查证缺口，不再承诺额外查询。保留原始用户文本、全部真实交换及 generation；没有增加工具额度或后台执行。写失败同样关闭工具，后续仍可如实说明失败。新回归在旧实现失败，补入指令后通过；提示本身不能保证模型遵守，因此另做真实复测。

Opus 的同角色、同时间、四轮复测共 6 次 Provider 和 4 次工具尝试。最终仍回答“官网页面暂时无法访问，我再尝试搜索一下其他可靠来源”，未完成要求的三条规则。新增关闭指令未解决这次实际失败，不能宣布收尾质量通过。六次短上下文对照中，Gemini 和 Opus 在单个、拆分、合并 system 消息下均正确返回指定控制标记；这排除了“这个端点总会丢掉前面的 system 消息”的简单解释，但没有验证完整角色或工具交换转发。原始指纹、usage 和校验和见 [后续探测元数据](tool-finalization-model-evidence-2026-10-01.json)；原始回复不回写。

当前 1.4.2 软件检查为定向 81 项、Python 全集 1658 通过 / 46 平台跳过，Ruff lint/格式及 Pyright 通过。真实模型复测使用该实现最终文本格式整理前的指纹，按元数据保留；这些证据均未用于质量放行。后续应针对工具决策上下文和最后回复的职责继续排查，不能继续仅凭提示文字或测试通过判断 Q02 完成。
