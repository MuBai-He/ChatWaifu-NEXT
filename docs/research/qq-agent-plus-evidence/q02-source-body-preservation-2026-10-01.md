# Q02 来源正文保留与输入复测

2026-10-01。本切片修复 `web.read` 的正文窗口与有明确标记的正文提取；不更换默认 persona、不扩大工具路由、权限或来源供应商。依据实际抓取的两份网页 DOM 定位缺口，不把法规答案、来源 URL 或删除关键词写进生产解析器。

## 复现与修复

旧读取器即使全文小于上限，也从 focus 命中点前 160 字开始返回。原旧页总可读文字 2350 字、上限 3000，却从偏移 915 开始，返回 1435 字，跳过前面的适用条件。新窗口在全文放得下时返回全部选定文字；长文在末尾命中时往前移动窗口，充分使用已有上限，并保留真实偏移、截断和 focus 状态。

两个实际页面把正文放在 `data-role="n_content"` 容器中，导航和页脚则是普通 `div`，未被原语义标签过滤识别。新解析器支持明确的 main/article、主内容角色、articleBody 和已核对的正文标记；只选择一个闭合、非空的最外层正文容器。独立正文容器有多个、未闭合或空白时回退原有可读全文。不会按通用 `content`/`bottom` 类名、正文词项或站点域名猜删内容；嵌套正文保留外层附件及条件，缩进、隐藏元素过滤和解析资源上限仍生效。

`web.read` 升级为 1.1.0，输出新增 `extraction_method` 和 `document_characters`。后者统计选择正文前的可读文字；`total_characters`、offset 和截断只描述选定正文。正文外的发布日期等元数据可能不包含，技能说明明确提醒：正文未截断不代表整页、更不代表全部适用规定或后续更新都已覆盖。原始 HTML 指纹、URL、抓取时间仍独立返回；来源指令继续作为不可信资料。评测器 1.6.1 保留原有实现/技能指纹与续跑身份，不混用旧批次。

## 实际来源和权限验证

在新隔离数据库中，以脚本 Provider 通过 Registry、逐次确认、Executor 和 Agent 实际读取两份公开来源；没有付费模型参与这一步。两次 `allow_once` 成功；另一次 deny 走 Runtime 未核实说明，无持久权限授予。初次脚本遗漏加密 DNS 参数，以默认系统 Fake-IP 解析失败；原失败 journal 和数据库保留，修正测试脚本后使用新目录，不改系统 DNS/代理。

段落计数含附件标题，并非规则数量。独立 HTML 扫描逐段核对正文，实际读取与先前 DOM 清点的原始字节 hash 相同。旧页实测使用 focus `100Wh`、上限 2000；模型回放保留原历史调用的另一定位词、上限 3000。用同一已抓取 HTML 离线验证，两组参数得到的全部返回字段一致，原因是完整正文能放入两个窗口且定位词都存在；没有声称两组调用参数相同。

## 三模型收尾重放与保留失败

复用已冻结的合成对话、候选 v5 角色和原搜索结果，仅替换两条读取结果，再各调用一次当前配置的 8318 端点。没有重新发现来源，也没有执行完整多轮 A/B。调用参数与配对保持原历史，新的抓取时间和提取元数据真实保留。收尾请求关闭工具，完整角色、当前任务和旧历史均保留，估算输入 6887；若重新带 schema，估算 8109，仍超过 7292 输入额度。

Claude 输入比上一轮 8393 减少 682，且本次低于 8192，但仍高于预留输入额度 7292；Sonnet 的实际输入加输出超过配置窗口。因此来源提取改善了输入开销，**没有证明跨 Provider 原生预算通过**。端点硬上限未知，reasoning 和价格仍未知，不补零。四次 Runtime Provider 尝试各有一对 started/finished，内部 HTTP 尝试上限合计 12，不等于已观察次数；供应商总量合计 30036 token。

主代理知道设计，直接读原文，非独立盲评。Gemini 保留了多项条件，但没有实际 URL，且先要求明确额定能量标识、后又允许由参数计算，表述存在矛盾。Sonnet 只写域名，漏个人自用及飞行中限制，并增加记录来源未支持的安检处置/申报断言；换算说明把 mAh 写成毫安。Opus 首次和单独同输入控制均正常 stop 却无正文，根因尚未确认，不能按协议完成判定回答成功。控制脚本请求后的原始 tuple/list 比较断言失败；以终态 journal 校验规范 JSON 后恢复结果，没有重发付费请求。既有 httpcore 清理告警保留。
