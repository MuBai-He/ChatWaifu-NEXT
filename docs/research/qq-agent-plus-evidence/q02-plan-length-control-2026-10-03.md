# Q02：规划长度提示的冻结输入对照

## 修改前依据与方案

完整批次的隐藏版本主审发现，普通文本和语音在确认、道谢后常重复建议或追加邀请。
这些轮次的实际 ResponsePlan 是 `response_length=normal`，但这只是相关性，不能
直接证明规划器压过角色提示。v8 已补通用收口契约，216 条定向复测仍有零星赘述。

本次仅做受控试验，先不改 `_plan_response`：选取已保存 v8 的普通文本/语音两种
presentation，各三个确认轮（问候第四轮、停止玩笑第四轮、情绪低落第四轮），加上
各一个明确请求完整代码的技术轮。八个锚点的用户输入、历史、角色、状态、预算完全
冻结，仅将系统中 Response Plan 的 `response length normal.` 换成 `short.`。
每个锚点按 normal、short、short、normal 各发两次，共三十二次真实模型请求。

使用服务器配置的 `gemini-3.8-flash-high` 和既有密钥，仅在远端进程内取用。
这些是无工具、无渠道副作用的冻结请求对照；统一关闭流式以记录响应 `model` 与 usage，
不等于重新执行 Runtime 多轮链路。实际请求正文、hash、用量缺报、延迟和回复均保存，
不保存凭据或隐式推理。请求无随机 seed，返回模型标签只作分组观察，不能证明底层权重。

判定看自然收束、人物表现、是否引入无依据动作/承诺，以及技术请求的内容完整性，
不能只数文字长度。32 次属于筛选样本；即便有改善，也要再设计保守触发与反例，
重新走真实三展示多轮评测后才能考虑实施。若没有一致改善，保留否定结果，不凭
`normal` 字样直接改规划器，也不修改生产 persona、预算、数据库或渠道设置。

## 结果：没有支持修改规划器的证据

32/32 次完成，开始与结束记录一一对应，均以 stop 结束。逐项还原请求确认，除规划
长度词外正文完全相同；流式开关在两组统一为关闭。先保存三十二项隐藏条件的主代理
判断及其 hash，再揭示映射。评审者是实现作者，不是独立人工或双盲评审。

| 筛选项 | normal | short |
| --- | ---: | ---: |
| 确认轮符合 / 部分符合 / 不符合 | 5 / 7 / 0 | 5 / 6 / 1 |
| 确认轮平均自然度（1–5） | 3.42 | 3.33 |
| 确认轮平均字符数 | 37.4 | 39.2 |
| 确认轮请求 p50/p95（ms） | 4588 / 21135 | 4616 / 13314 |
| 完整代码任务符合 / 部分符合 | 4 / 0 | 3 / 1 |

每组十二条确认回复的实际响应标签均为 flash/control 各六条；技术任务各两条。
按标签分组后，确认轮两种长度条件的符合数仍分别为 flash 3/6、control 2/6。
这只排除了本小批标签数量不平衡，不能据此证明标签代表相同或不同权重。

`short` 没有减少多余的休息安排、泛化邀请；它也不是直接截字数的机制。八段完整
asyncio 示例逐段检查后在服务器 Python 隔离子进程中执行，全部退出 0；七段声称的
stdout 均逐字一致，另一段没有声称具体 stdout。一个 short 回复的尾句泛称保证
所有任务完成，记为范围表述的软性问题：本例 ValueError 成立，未覆盖外部取消。
没有观察到本组短提示把完整代码截断，但不能推出所有详细任务都不会被影响。

供应商报告输入 68864、completion 13362、total 82226 token；reasoning 仅 21/32
次有值，已知小计 10175。这里保存的是 non-stream 原始 usage，completion 包含
已报告的 reasoning（total 等于 prompt 加 completion），不得再加一次，也不得与
此前 SSE Adapter 的正文计数不加说明地比较。美元费用未知。

保留 `_plan_response` 原样，继续从实际语义和剩余场景证据决定修改。完整原始请求、
隐藏条件判断、揭示后分组、执行输出与九个远端文件的 hash 校验见
[对照证据](q02-plan-length-control-2026-10-03/)。凭据扫描无命中。该否定性试验不是
Q02 通过依据，也没有重新验收 TTS、播放或外部渠道。
