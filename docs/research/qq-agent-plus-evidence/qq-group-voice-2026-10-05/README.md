## 范围与故障依据

用户改变原群聊只回复文字的约束，明确只为既有指定群开放“平时文字，当前发言者明确要求时才允许语音”。其他群、私聊、微信、桌宠/Web 对话策略保持。原 21:24:09 群请求完成并只生成文字，入口当时禁用全部工具，没有进入语音合成；角色同时拒绝了要求说的内容，介质权限与内容选择须分别判断。此前纯 @/指代修补的用户可用反馈仍有效，见[原证据](../qq-mention-reference-fix-2026-10-05/README.md)。

[ADR 0076](../../../adr/0076-opt-in-qq-group-requested-voice.md) 增加默认关闭的 `allow_requested_voice`，存入路由及其不可变版本；旧客户端更新时省略/null 保留设置。只有本轮已授权群发言、真实当前请求、仍有效的路由/受众/连接/生成，才能看到并调用唯一 `channel.voice` 工具；引用、旁听、旧历史、纯 @、否定和概念解释不授权。保守识别只作用于群入口，不强制模型发送语音，也不替换私聊的语义选择。复杂表达可能仍需改成明确的“用语音说一句晚安”。

复用当前角色 TTS、2000 字/120 秒/8 MiB WAV 上限、OneBot 原生 record 和收据检查。群语音在生成运行时原子创建唯一音频计划，完成后保留实际说出的正文，不再重复发文字。明确失败与结果未确认使用不同文字降级，保留原音频审计；不重放未知发送。新 @、撤销、成员变化、重连与迟到合成取消旧流程。迁移 43 保留旧事实/校验和，仅添加默认关闭字段及受限音频/降级守卫。
