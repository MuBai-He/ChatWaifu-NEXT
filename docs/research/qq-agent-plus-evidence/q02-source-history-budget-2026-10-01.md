# Q02：旧助手措辞省略后保留原始来源资格

2026-10-01。跨轮来源切片之后的实际两轮回归发现：PromptCompiler 从 selected_entries 选来源 generation，旧助手回复过长而被 conversation budget 省略时，尚在缓存中的完整原文也不会传给下一轮。这是已复现的链路缺口，不是仅凭源码推测。前一焦点测试提交为 1922d4c；本切片没有新的付费模型调用，也未使用 AGY。

失败控制经过真实 Conversation、allow_once 权限与 builtin READ/SkillRun 路径。第一轮读取仅个人自用、例外需事先审批的合成原文，受控助手只输出很长的“已读”措辞，没有复述原文条件。第二轮要求出发前清单：编译报告明确省略两个历史条目，原文仍在 ephemeral 缓存，但实际 Provider 请求只有摘要，没有原文或来源 JSON。修改前测试在原文断言失败。

现在来源 generation 从 prepared、已脱敏历史独立选取，文本预算仅决定旧措辞是否进入请求。最多八个同稳定路由的助手 generation，仍核对当前 session 和 completed 状态；原文投影继续整份保留或按冻结预算明确省略，不从摘要恢复或重放工具。展示名称/时间不授予读取权限。没有新协议、数据表、长期记忆或审计正文保留。见 [ADR 0060](../../adr/0060-bounded-cross-turn-public-source-context.md)。

修复后的实际两轮请求仍省略旧措辞，但包含原文、URL 与读取时间，原文只进入不可信 user-role 资料，工具只执行一次，持久审计仍不含原文及私有 URL 查询值。新增编译控制覆盖预算省略的同路由、脱敏、其他发送者和未知 ID；只有第一种保留来源资格。既有八键路由、数量/去重、重启/淘汰、reset、权限拒绝、外会话、未完成生成与加载中取消控制均保留。

评测器升为 1.8.1，使用相同编译结果与既有实现指纹，不能混用先前批次续跑。定向 101 项、完整 Python **1764 通过 / 46 平台跳过**；Ruff/格式、Pyright 零错误/警告和架构边界检查通过。Web 312 项、lint/typecheck、Web 构建、正式 build:desktop-ui 脚本、文档构建与 Prettier 通过，协议生成无差异。第一次桌面过滤命令没有匹配项目，不能算构建；已使用仓库正式脚本成功重跑，原日志保留。本提交 CI 另验。旧 CI 失败继续保留，不借父提交或本地成功批准本提交。

本次证明来源资格不会随旧措辞的预算省略而消失，尚不证明真实模型保留条件、来源当前有效、原生 token 上界或 Q02 通过。下一步在当前 8318 配置复测来源/清单，并检查换话题与告别后不会被旧资料拉回任务；技术正确性、完整十二场景、三种 presentation 与受控 Runtime 交互验收继续开放。默认 persona v4 和 PR 草稿保持。
