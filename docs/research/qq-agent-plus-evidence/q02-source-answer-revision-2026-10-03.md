# Q02：固定 Gemini 3.8 Flash 的来源答复核对

本轮由主代理直接实现和审查，未使用 AGY。候选调试和后续评测固定使用
`gemini-3.8-flash-high`。服务器继续使用 SearXNG + Crawl4AI，公网读取显式设置
`dns_resolver=cloudflare`。Jina 和其他 Gemini 路由的历史诊断不作为当前候选方案。

## 调查依据与候选选择

此前实际 HTTP 请求捕获已经确认：来源正文和引用要求确实进入了模型请求。
因此不能把所有回答缺引用、范围错误归因于搜索服务，或继续以缩短输入作为修复。
固定相同来源、问题、历史和模型预算的后续诊断保留在
[q02-server-deployed-vs-jina-2026-10-03](q02-server-deployed-vs-jina-2026-10-03/)：

- `role-persona-controls`：角色/中性提示与工具/用户数据角色共四组、每组三次。
  只有中性工具角色组一次保留两个实际 URL，其余均缺引用；没有采用角色替换。
- `endpoint-canaries`：六个短输入控制均遵守系统优先级、原样 URL 和后缀要求。
  这只排除了“该端点总是丢弃系统要求或 URL”的简单解释，未证明代理内部机制或底层模型身份。
- `citation-correction-controls`：只要求补引用的三次控制均有两个 URL，但仍出现
  缩窄召回主体、以部分条件保证放行的错误，不能只按 URL 出现判通过。
- `flash-draft-revision`：把三份真实未交付草稿与同一原始来源一起核对，每份重复三次。
  主代理逐份阅读，九次均保留两个来源链接、容量边界和召回型号/批次，未再出现
  原先的部分条件保证。仅为这一固定问题的诊断，不是全场景通过或法规现行性确认。

九次定向控制的供应商 prompt/completion/reasoning/total 为
`104841/4708/17821/127370`，新增核对请求延迟 p50/p95 为 `9359/12306 ms`
（nearest-rank，小样本）。实际 payload、原始回复、用量及脚本均已保存。这是明确的
时间和 token 成本；不能把新增核对当作免费或即时。没有调整模型总窗口来获得该结果。

## 实现边界

- 在成功读取原文后的答复交付前，增加最多一次同模型、无工具的答复核对。
  核对保留用户问题、角色、历史、原文结果、generation 和冻结输入/输出预算；草稿作为
  不可信 JSON 提供，不能以草稿自证。正文没有被核对层再次裁剪。
- 核对要求保留适用范围、条件并列关系、数值边界、例外及真实来源 URL，资料不足须说明。
  这不是事实判定器，不把模型自检结果记录为“质量通过”。
- 来源整理清单也使用一次核对，但只允许仍在当前请求中保留完整结果的成功 READ 收据。
  原文不可用、失败或因预算省略时，元数据中的 URL 不能冒充核对依据。换话题不会仅因
  历史中存在来源而增加核对。
- 核对阶段不执行工具。超预算返回明确失败说明；空、截断、无终态或试图调用工具的
  核对不会交付草稿。取消和 generation 失效时丢弃输出并关闭模型流。
- 来源补读候选按搜索摘要对“尚缺条件”的覆盖数量排序，优先完整匹配，再保留部分匹配。
  摘要只用于选择待读 URL；仍须通过原有权限和正文读取检查。
- 评测器升级为 1.18.0，新增源码进入实现指纹。核对轮次计入实际调用和供应商用量，
  旧批次保留原身份，不与新实现混合续跑。

模型预算沿用上下文 32768、输出预留/上限 8192、估算余量 15%、scaled 分项、历史 32、
记忆候选 24、工具结果上限 131072 字节。参考 tokenizer 不是 Gemini 原生计数，
输入未超限不能证明回复正确；Crawl4AI Reader 仍有独立的 6000 字片段上限。

主代理针对失败项目阅读复核后保留以下结论，不把 `fact-audit --check` 的 3/3
提及覆盖升级为事实批准：

- 六份法规/清单均带实际读取链接，并保留 3C、召回型号或批次。r0/r1 的容量分支
  保留 `≤100`、`>100 且 ≤160`、`>160`，没有旧版的 100Wh 分支重叠。
- r2 读取的是 2015 年禁限条件新闻与 2025 年更新，正文没有完整说明 ≤100Wh 分支；
  两份回答沿用高容量档规定，没有明确交代低档信息缺口。法规轮还补入未附证据的
  标称参数/USB 换算说明。因此仅靠“额定能量/3C/召回”出现的来源闸门仍不够。
- r1 使用了扬子晚报转载说明机上使用等细则；它确实经过读取，但不是新增的官方原始
  规范核验，不能据此宣布已确认所有当前规定。
- Raft r1/r2 仍把 heartbeat interval 插入所谓必须满足的论文不等式；r0 将时序
  条件同时归因于安全性和可用性，也需修正。参照
  [Raft 论文 §5.2/§5.6](https://raft.github.io/raft.pdf)，技术正确性门槛未通过。
  三轮未读取外部原文，不把这类错误归因于 Crawl4AI 或输入不足。
- Python 五段完整示例均在服务器 Python 中实际运行，exit 0；唯一显式给出的
  逐行输出与实际输出一致。默认异常传播和 return_exceptions 说明与
  [Python 3.12 官方文档](https://docs.python.org/3.12/library/asyncio-task.html#asyncio.gather)
  的对应行为一致。这只覆盖展示的普通 Exception 场景，不证明所有取消组合都正确。

本批为单候选的定向回归，不是与旧版同时配对的盲评。六次核对只减少了来源引用和
条件改写问题，未使模型质量整体达标；未据此启动全 432 条发布验收或部署候选。

## 流关闭修复

先前全部回复记录完成后出现 `generator didn't stop after athrow()`，不能因为进程
exit 0 就忽略。回归复现定位到提前结束 SSE 消费后，HTTP 文本迭代器没有确定关闭内部
字节迭代器。适配器现在显式持有并关闭解压字节流和每次尝试，增量解码 UTF-8/BOM，
处理跨分片 CR/LF/CRLF，保留用量尾帧和正常 EOF。协议行为参照
[WHATWG SSE 解释规则](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation)。

新增测试覆盖提前终止、消费方关闭、读取中取消、错误帧、gzip、分片多字节字符/BOM、
换行与无 DONE 的 EOF。修复前新检查 6 失败 / 1 通过；随后另补 2 项 EOF 测试。
`stream-lifecycle-fix` 保存补丁和阶段性检查记录。九次 3.8 Flash 核对和上述 12 条
Runtime 实测没有再次观察到该关闭异常；这是当前观测范围。
