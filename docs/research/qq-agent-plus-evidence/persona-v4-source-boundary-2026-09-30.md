# CW-Q02 候选 v4 人设来源边界与待测实验设计

2026-09-30，基于 Astra 对 v3 全量 A/B 复核结论的设计决策，实施默认角色绫地宁宁人设（persona v4）的精简与来源边界修正。

## 1. 设计范围与边界决策

本次变更仅限 `characters/default/persona.md` 及配套的基础单元/集成测试：

- **PromptCompiler 保持不变**：不修改编译器模板、预算分配算法或系统提示拼接逻辑，确保后续 v3 与 v4 在相同的编译器基准下开展纯人设比较。
- **不修改系统其他模块**：Planner、协议、生成路由、生产工具、配置以及历史真实模型实验证据与 fixtures 保持严格只读。
- **完整保留核心约束**：
  - 绫地宁宁外在温柔认真、亲切体贴，熟悉后害羞慌张稍微笨拙的原作性格；
  - 五级冲突优先级结构（来源事实 > 用户边界与任务 > 关系阶段 > 个性表达 > 短消息风格）；
  - 诚实非官方 Demo 身份声明与模型部署方式未知（不猜测本地/云端/供应商）；
  - 关系阶段逐步发展约束；
  - 严肃技术求助与详细解答完整作答规则；
  - 停止玩笑/正事衔接以及道别收口规则；
  - 基于真实来源凭据的共同经历记忆机制；
  - 六组原始参考示例（被调侃、停止玩笑、认真求助、记忆不足、明确道别、身份边界）。

## 2. 来源边界与通用规则修正

针对 v3 盲评与主代理复核中暴露的“过度泛化记忆依赖”问题（如模型将通用知识误当成共同经历而拒答、反问是否需要回答明确问题、在口味偏好中机械声明无进食身体等），v4 引入四项高度概括的通用规则，不包含任何特定场景 ID 或领域专有名词：

1. **通用知识与客观解答独立性**：明确通用知识不受 Memory Context 约束。Runtime 提供的记忆与历史用于支撑个人与共同经历事实；当前用户陈述归属于用户，不等于角色经历过该事件，绝不编造未发生的共同经历或假装现实动作。
2. **缺历史不扣留显式问题解答**：若用户提问预设了此前讨论但历史记录缺失，绝不能因此扣留对当前已明确提出的客观/技术问题的解答；必要时简述未见记录并直接作答，不反问是否需要回答已清晰的请求。
3. **自然表达偏好与真实身份平衡**：角色互动中自然表达符合人设的偏好（如口味、兴趣），无需机械声明自己缺乏物理现实体验；偏好不授权虚构现实动作或伪造经历。面对现实性、能力或身份的直接询问依然保持诚实，不设一刀切禁止说明 AI/非人。
4. **通用时效性与不确定性指引**：缺乏确切依据或具时效性的事实承认不确定，不臆测标准或数值。人设中不硬编码充电宝、民航局、3C、电压、asyncio、Raft 等任何领域事实，既不把法规答案伪装为人设，也不引入脆弱的模板特化。充电宝等客观事实能力仍由知识检索/工具能力界定，事实门槛保持开放。

## 3. 预算压缩与装载度量

在保证原有约束与示例完全保留的前提下，精简了前言与优先级描述中的冗余字句，确保完整装载后处于安全预算内：

- **原始 persona (v3)**：1300 字符，650 估算 token。
- **候选 persona (v4)**：1357 字符，679 估算 token。
- **预算控制**：在 CharacterLoader 与 PromptCompiler 最小上下文窗口（1024 token）分配的 700 token 最小 persona 预算下，v4 实际占用 679 token，严格满足 `<=700` 上限且达成 `<=680` 安全余量目标，编译输出无截断省略号（`…`）。
- **候选包哈希**：`characters/default` 目录 Package SHA256 为 `63f6fd28b523af9efae712511e83867c7631954669edb9db2018bd72ac734f8a`。
- **原始 persona 字节哈希**：v3 为 `7f9daf3c6cefd57f`，v4 为 `3ab060352dcb8e25`（SHA256 前 16 位）；包哈希与 persona 单文件哈希含义不同。
- **Profile 覆盖**：在 `instant_message`、`single_text` 及默认 `voice` (None) 三种 presentation profile 下，编译后的 system prompt 均完整保留 `[CHARACTER CANON]` 与来源/偏好边界准则。

## 4. 待开展的模型实验（Pending Model Experiment）

本次工程切片未调用外部模型端点，亦未捏造模型输出。后续计划在相同实验框架下进行 v3 对 v4 的 A/B 评测：

1. **测试基准与端点**：沿用 HTTPS 8318 端点与相同三个模型（Gemini 3.8 Flash High、Claude Sonnet 4.6、Claude Opus 4.6 Thinking）。
2. **场景集**：从现有 12 组四轮场景中选取话题切换、技术求助、详细回答、共同经历不足、身份、停止玩笑六组，重复三次、两版本比较；每模型 144 条，三个模型合计 432 条。基线为冻结的 v3，而非最初的旧 persona；该定向实验不能替代全部场景的发布评估。重点观测：
   - `topic_switch` 场景下预设前情缺失时是否直接回答技术问题，不再反问推脱；
   - 日常偏好与口味场景下是否自然流露人设喜好，不再机械声明“无身体/未进食”；
   - 停止玩笑、严肃正事衔接以及道别收口是否保持稳定；
   - 真实身份与模型部署未知边界在本样本中是否出现回归。
3. **独立覆盖审计与人工复核**：沿用事实覆盖审计脚本与 AGY 盲评机制，客观记录退化与提升项，完成最终放行门槛核验。
