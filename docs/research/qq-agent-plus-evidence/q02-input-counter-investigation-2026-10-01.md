## 同一端点的计数观察

当前 8318 端点在一次合成 Hello 请求中支持 `messages/count_tokens` 路径，HTTP 200、input_tokens=1。随后以 Messages 的 system、text、tool_use、tool_result 结构表达三份已测合成输入；system/context/history 和完整来源结果哈希均与先前实际生成请求匹配。计数请求保留完整工具资料，没有执行工具，也没有调用生成模型。

| 输入                         | 先前生成请求报告的输入 | 本次计数返回 | 差值  |
| ---------------------------- | ---------------------- | ------------ | ----- |
| 原来源、已有预算投影         | 8393                   | 97           | -8296 |
| 保留完整来源、旧助手历史仍在 | 7711                   | 665          | -7046 |
| 同一完整来源、省略旧助手历史 | 6855                   | 97           | -6758 |

这些差值不足以证明计数服务的实现根因，也未证明代理内部的 Chat Completions → Messages 转换与本次表达完全一致；**HTTP 200 不足以把这个计数当作预算依据**。原旧来源和新来源在省略历史后都返回 97，而保留旧助手文本时返回 665，这支持继续调查字段覆盖和转换。不能将其扩展为该端点的所有工具、system 或模型都被忽略的结论。

Anthropic 的[正式计数接口说明](https://platform.claude.com/docs/en/build-with-claude/token-counting)支持 system 和工具等结构化输入，同时说明其结果仍是估算。本轮只是现有代理路径的观察，没有确认它透传该正式服务或使用其 tokenizer。四次计数客户端 HTTP 请求、零生成请求；代理内部尝试、费用与账单未知，计数结果不作为新增生成用量记账。全部数值和唯一的旧生成 call_id 见[证据](input-counter-investigation-evidence-2026-10-01.json)，完整请求和网页正文只保留本地。

| 原来源、已有预算投影         | 7255             | 8393             | 8687                  | 6711                 |
| 保留完整来源、旧助手历史仍在 | 6887             | 7711             | 7862                  | 6112                 |

JSON 参考包含序列化结构和转义，不等同于服务端聊天消息计费格式；cl100k 在这两个输入中高于已报用量，不能推广为全模型的上界。o200k 则明显低于所测 Claude 报告值。实际新输入为 13465 字符、3973 个非 ASCII 字符；本地两字符启发式与参考编码各有偏差，当前预算验收继续失败。

调查中保留两类修正：临时环境没有展开工作区的 editable 源路径，脚本补显式源路径后运行；最初旧来源比较误用了未投影历史与已投影 usage 配对，已排除。最终改用原拟合请求，在原 system/context/history 和完整结果哈希核对后记录上述表格。已有输出目录冲突也保留，改用不同目录，没有覆盖或重发生成请求。
