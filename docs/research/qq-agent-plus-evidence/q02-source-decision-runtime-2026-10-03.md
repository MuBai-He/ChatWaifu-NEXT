# Q02：隔离来源决策与真实 Runtime 执行

本轮按[事先记录的方案](q02-source-decision-contract-2026-10-03.md)实现了 opt-in 评估切片。Q02 验收保持开放；来源契约通过和工具成功不能代替最终答复质量。

## 实现边界

新增 `--source-decision-contract`，只在隔离 `RuntimeSourceEvaluation` 中生效。普通聊天、初次原生技能选择、生产 Agent 和运行中的模型/预算/persona 配置保持原行为。后续纯 web.search/web.read 回合使用版本化 native decision，实际动作仍经过原 Agent、权限确认、Runtime Skill 执行与来源收据；临时记录不会进入长期记忆。

[实现](../../../tools/source_decision_evaluation.py)将原始模型决策与通过校验的技能投影分开记录。后续实际发送的 native history 保留原始函数名、call ID 和完整参数，tool result 内另列实际执行调用和真实结果。`validated_projection` 只代表映射通过校验，是否执行以及成功与否必须查同 ID 的 SkillRun。失败的 v18 早期字段名 `executed_projection` 已更正，历史原始记录保留。

校验覆盖版本/结构、数量、长度、URL 收据归属、参数、重复调用、拒绝后重试和结束决定的自相矛盾。已识别、可读而尚未读过的相关线索，在有剩余调用时不能通过改叫 `finish_with_gaps` 提前放弃。失败/拒绝则允许如实说明缺口。原有六次来源调用上限不变，整个 generation 最多一次契约纠正；所有额外请求经最内层原始 recorder 计数，实际变换后的 schema/history 再做输入预算检查，保留已有省略记录。

模型自填的发布者、范围、日期和完整性不是事实证据；模型仍可能漏列已出现的更新。已读页面也可能只包含转载或局部摘录。最终回答继续经过现有无工具修订，并独立做事实、来源和任务保真复核。

## 真实失败与修复

同一服务器、`gemini-3.8-flash-high`、SearXNG 18081 / Crawl4AI 0.9.3 11236，公网读取使用 `dns_resolver=cloudflare`。沿用 v17 的两组四轮、单文本展示、候选 v7、32768 上下文、8192 输出预留及 15% 估算余量。真实搜索结果和模型采样可能变化，以下不是固定资料的因果 A/B。

| 快照 | 实际结果                                                                                                                                                  | 决定                                                                                     |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| v18  | 首轮失败；3 次模型请求，1 次真实 search 成功。两次决策均把字符串版本 `"1.0"` 返回为数字 `1`。                                                             | schema 显式声明字符串类型和枚举；数字版本仍拒绝，未放松运行时验证。                      |
| v19  | 首轮失败；6 次模型请求，1 次 search、2 次原论文 read 成功。结束时先返回普通文本，纠正后又生成不合 schema 的 `finish`。                                    | 将条件动作结构改为固定字段的 v2；运行时继续用所选技能的原始完整 schema 校验参数。        |

| v21  | 完成 8/8 轮，21 次请求；5 次 search、2 次 read 成功，其中一次搜索为零结果。一次动作结构错误经唯一一次契约纠正恢复。                                       | 原生决策→真实技能执行→无工具修订整条链路跑通；保留为隔离候选，质量门槛继续开放。         |

v18 原始 Provider 用量为 prompt **12215**、completion **297**、reasoning **5752**、total **18264**；v19 分别为 **32598 / 2374 / 13129 / 48101**。这里是 Runtime 的拆分用量，不能再把包含 reasoning 的原始 API completion 重复相加。两个失败批次均无历史/工具前言省略；参考估算相对供应商输入计数的误差分别为 **+0.26%～+16.87%**、**−0.20%～+18.01%**。

各批次的实际模型决定、实际技能收据、HTTP JSON、记账和调用映射审计均保留于[证据目录](q02-source-decision-runtime-2026-10-03/)。失败批次按实际失败记录，不记成八轮完成，也不把未展示的草稿当作用户收到的答复。每批原始产物复制后与服务器 SHA256 一致，已用实际配置的凭据做不回显扫描；变换器和 recorder 的各版源码另存为 `.py.txt`，便于复核。

v20 用量为 prompt **106782**、completion **5160**、total **120529**，15/16 次有 reasoning 明细，已知小计 **8587**；不能把缺失明细当零。已完成五轮 p50/p95 为 **7636/62614ms**。实际 HTTP 与 Provider journal 一一对应，无历史或前言省略；参考计数误差 **−1.10%～+36.13%**。五条展示完整性检查通过，但非盲逐条质量复核仍未通过：Raft 最终修订确实删除了“每次心跳都重新抽样”的草稿说法，固定心跳和一般工程配置的表述仍需限缩；旅行建议仍泛化公共交通的 100Wh 标准。已执行工具统计包含失败轮，不能只看已完成 results 的小计。[完整逐条复核](q02-source-decision-runtime-2026-10-03/v20-smoke/primary-review.json)。

## v21 完整八轮的实际结论

21 次真实请求均指定 3.8 Flash High，全部终态；八份最终回复均来自真实 Provider 的无工具文本输出，没有 Runtime fallback。prompt **138137**、completion **8002**、total **153708**；11/21 次有 reasoning 明细，已知小计 **7569**。八轮 p50/p95 **6678/101531ms**。没有历史或工具前言预算省略，参考计数相对供应商输入误差 **−6.36%～+36.13%**，这只是观察范围，不是参考计数或 15% 余量的普遍误差保证。

完整调用映射审计通过，八条机械展示检查通过，选定法规词项审计通过。主代理非盲逐条复核仍为 **质量未通过**：

- 法规轮实际发现并读到了 2026 年报道，保留每人总量两块、3C/召回、Wh 分档等条件；最终修订删掉草稿中正文未支持的换算公式。清单保留两项独立活动、各自 2.5–3h / 2–3h 用时及数量，没有再编造入馆截止时刻。
- 但它只读了一篇转载自“重庆飞Fly”的重庆日报网页，没有追到原始规范；直接回答没有标明发布日期与这个核实缺口，仍把转载条件宽泛呈现为境内航班规则。来源记录自己承认这是媒体报道，却仍选择 `finish_with_evidence`，说明结构合法不等于权威性或适用范围已核实。
- Raft 最终表达改善了固定参数泛化，但这次只读论文 5.6 附近的 6000 字符摘录（偏移 47487 / 文档 91168），未读到 5.2 的 150–300ms 示例，却仍引用该数值。这里数值本身可以在整篇论文核实，问题是本次实际提供的摘录没有支持它。**扩大总输入窗口没有取消 Reader 的独立 6000 字符上限**；需要补读相关章节，不能把仅有成功读收据当成整篇已读。
- 旅行初始建议又把 20000mAh 泛化成民航/铁路合规条件。清单最终没有保留该数字，但首轮无来源的外部规范断言仍需修复。
