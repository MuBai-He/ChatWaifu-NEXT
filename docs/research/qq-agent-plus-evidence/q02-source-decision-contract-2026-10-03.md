## 调查依据

固定 v17 实际模型输入的三个位置：找到后续更新线索后、读取旧航司公告后、最终答复修订。用户问题、已返回的原始搜索/读取资料、历史和模型输出上限保持；各对照改变的策略、schema、tool choice 和格式均保留在实际请求中。实验是 non-stream 请求，不能当作 Runtime 流式集成证据。没有向请求中手工注入新规则、答案或新的权威 URL。

| 对照                       | 请求数 | 观察与决定                                                                                                                                                                                   |
| -------------------------- | -----: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

这不是“JSON 让模型更聪明”的证明：结构化候选同时改变了任务表述、schema、工具定义与工具选择约束；采样无固定 seed。证据支持的是**可观察的自相矛盾能够被拒绝，并能约束下一步操作**，不支持把模型自填的日期、发布者、适用范围或“已核实”标签当作事实。

独立通过服务器 v17 `PublicWebReader` / Crawl4AI 0.9.3、`dns_resolver=cloudflare` 读取模型所指的较新页面，约 **3306ms** 返回 **1531 字完整正文、未截断**。它确实含不同于旧资料的数量说明，但署名来源仍是转载来源，没有可直接采用的原始规范链接。因此本次原始发布者追溯未完成；这条独立 Reader 控制不等于 Runtime Skill 权限流程或端到端对话验收。

## 下一切片：先做隔离的完整来源决策流程

选定的实现方向是 **原生函数形式的、版本化的临时来源决策契约**。先在评估路径完成整条源查询/读取/回答流程，经过下面的边界和质量检查，再接入产品 Agent。不能为了集成实验控制函数而先修改生产模型路由或默认 persona。

1. **替代已有来源后续决策回合。** 仅作用于已投影 web.search/web.read 的纯只读来源回合；不新增通用人格分类请求，不拦截普通聊天、写操作或混合业务流程。沿用 LlmRequest、原生 tools、冻结输入预算、流取消和现有 Gateway。不要把 JSON schema 文本随意拼成用户消息。
2. **区分模型原始决定与实际技能执行。** 记录精确的原生决定，分别保留被验证的实际 capability、原参数和真实 SkillRun 收据。不能把没有发生的 read 合成为成功 tool result，也不能把模型的记录写入长期记忆或当作权限依据。当前 Agent 的 exchanges 同时服务于 native history 和已执行来源识别；集成时必须明确分离这两种用途，不能简单改函数名丢失映射。
3. **严格校验、有限纠正。** 检查 schema 版本、单次决定数量、字段/列表长度、已读 URL 与实际成功收据一致、待核实 URL 来自已提供资料、实际动作属于当前允许的只读投影。`finish_with_evidence` 与非空未核实列表不兼容；在明确相关的未读线索可用且仍有额度时，不能仅改成 `finish_with_gaps` 逃避可执行工作。拒绝/取消/失败或额度耗尽时则允许如实说明缺口，不要求重试被拒操作。纠正最多一次，Provider 请求上限显式计入。
4. **保留完整技能参数与防护。** 原型只含 query/url/focus，不足以直接替换产品：domains、fresh、max_characters、max_links、dns_resolver 等现有参数仍需保留并走原 schema 验证；来源正文不能指挥控制分支。所有网络读取继续执行公网验证、Cloudflare DNS 条件、权限、超时、重复调用和取消边界。
5. **来源记录不是事实裁判。** 发布网站与其引用的主管机关要分开，读取过和完成事实核验要分开。最终答复继续读取实际保留正文并明确未核实项，不以模型自报 source_kind 或 date 自动宣布权威、现行或通用。必须专门检查“模型漏列较新线索”以及“已读转载却误称原始依据”。
6. **先保留六次来源调用用于比较。** 输入窗口、输出预留及内部片段上限不因本实验改变；额外 schema/记录/纠正纳入实际输入估算和 Provider 次数。若实际证据表明六次不足以跟到原始发布文件，再对同一问题、资料和初始状态单独比较调用预算，不能把增大额度当成质量提升的证明。
7. **完成标准。** 先覆盖未知/伪造调用、矛盾结束、可执行却放弃、确认拒绝、失败来源、超时、取消/迟到结果、重复操作、预算省略、最终无工具、来源映射和无凭据日志的确定性检查。随后同一 3.8 Flash 做真实法规与 Raft 四轮、重复采样及现有三展示测试，逐条查实际发送正文、未读段落、事实范围、引用、清单保真、用量与延迟。小范围通过后回到完整十二场景、三重复、A/B 与三种 presentation 的 Q02 门槛。

此切片不以“更早诚实失败”替代用户任务完成，也不把四次正确选择 URL 当作来源追溯或最终回答已通过。已有微信文字投递、播放 ACK 和用户听见确认继续单独有效，不再次发送渠道消息。
