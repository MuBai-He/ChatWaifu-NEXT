# Q02 来源发现与 Runtime 模型评测

2026-09-30。`web.read` 已有实际公开来源读取证据，但原 Q01/Q02 评估器直接调用 Provider；缺少 URL 的问题仍没有实际来源发现。当前公开入口探测中，DuckDuckGo HTML 返回 202 挑战页，Google/Baidu 没有可读内容，Bing 两次结果与查询不相关。DuckDuckGo Lite 曾返回相关民航局结果，但另一次使用不同 User-Agent 的原始探测收到挑战页；不能将它当作稳定服务保证。按 [DuckDuckGo 官方说明](https://safe.duckduckgo.com/duckduckgo-help-pages/features/non-javascript)使用公开 Lite 入口，固定应用标识，不绕过挑战页，不自动切换供应商。

新增 `web.search` 1.0.0，属于现有 `runtime_skills`：输入查询、可选域名限制、最大结果数和显式 DNS 方式；输出搜索入口、UTC 抓取时间、页面指纹、实际标题/URL/片段、过滤和截断元数据。搜索片段不作为最终事实证明，需用 `web.read` 读取实际来源。查询会发给 DuckDuckGo；安装与 `web.public.search` 授权分离，逐次确认后才发网络请求，30 秒超时，父取消传播。既有公共地址/DNS 固定、重定向与体积限制共用，所有结果不可信，不写长期记忆；普通 Runtime 审计不记录查询或正文，显式本地评测产物另行保留完整工具结果。

公共 HTTP 读取只提取一个内部、与 SDK 无关的页面记录，供读取和搜索适配器共用。不得放宽 `web.read` 的网段/协议/证书限制。搜索解析限节点/深度，最多五条结果，解开实际 DuckDuckGo 跳转参数、去重并检查 URL；域名限制同时用于查询和实际结果过滤。无结果、来源被过滤、挑战/格式变化、HTTP 失败分别记录，不能把登录/挑战页当作零结果成功。HTML 会变化，因此实际探测和真实模型复评独立于受控解析测试。

Runtime 评估仍使用真实 PromptCompiler 和固定状态。工具路径必须在隔离数据库中走 Router → Registry → PermissionBroker → Executor → Adapter，仅允许读取/搜索；允许一次的确认属于显式测试策略，不能给生产会话授权。记录每次实际 Provider 轮次、实际工具调用/返回、各轮 usage 和失败，保持角色版本、状态与输入可核对；不能将旧直连模型结果补造为工具测试，也不能将检索到关键词等同任务正确。每轮最多四次工具调用，另设实际 Provider 轮次上限，超时/取消保存已完成证据。历史 A/B 原始文件、计费信息和隐藏标签评审保持原字节。

验收顺序为：失败回归 → 公共网络/解析与权限测试 → 实际搜索及来源读取 → 指定三模型的受控 Runtime 工具链 → 原十二场景与三种 presentation 门槛。搜索不可用时如实返回失败，继续保留 Q02 未通过；不凭窄场景或自动测试批准发布。

## 已实现与验证

运行器升级为 **1.3.0**，默认仍是原直连路径。显式 `--runtime-source-tools --allow-source-tools-once --max-provider-requests N` 才启动隔离来源工具链；真实远端模式同时要求 `--no-cost-ceiling`，因为后续工具正文和实际调用轮数不能由旧 token 粗估封顶。`--max-requests` 计逻辑场景轮次，新上限计实际 Provider stream 调用；适配器内部 HTTP 重试最多三次，另算，不能称为账单硬上限。

每次 Provider 调用先写开始记录，再派发请求，完成或取消后写结束记录；续跑包括未完成尝试的计数，丢失已记录尝试的 journal 时拒绝续跑。实现及 manifest 指纹、DNS 选项和权限策略参与续跑身份检查。完整模型调用、工具结果和原始 usage 只保存在显式评测产物，普通 Runtime 审计仍隐藏查询及正文；缺失 usage 不补零。模型没有执行初始必需工具时，返回 Runtime 回退并明确标记来源，不能将回退当成模型正常回答或查询成功。

实际首轮暴露两个召回缺口：民航“携带规定”没有匹配 manifest 的“法规”；网页描述中的“可用”与问题的“正常结果”共享状态概念，“作为”也导致弱词误召回。新增通用法规语言归一，并将 `web.read` 的说明改为不含这些误召回词的 **1.0.1**；没有增加按 Skill 名称或场景答案分支的路由。Agent 工具 policy 要求发现来源后读取原文，不用搜索片段冒充核实。

解析与权限测试、实际搜索→原文读取、拒绝后零联网、取消关闭、部分 usage、Provider 上限与重启计数、回退和缺终态均有回归。最终 Python 全集 **1642 通过 / 46 平台跳过**，全仓 Ruff、Pyright、Web/桌面构建通过；只有已有 audioop 和前端分块/动态导入提示。第一次完整回归的 1638 项是在随后路由修正之前，不混用为最终结果。

## 真实模型证据与限制

同一当前配置的 8318 端点、指定三模型、同一 v5 候选和新状态夹具，在两个场景各四轮、一次重复中先后完成两批，各 **24 条**。首批全部零工具执行，六条技术回复变成 Runtime 回退；原始结果保留。修正召回后的第二批：Gemini 8 次 Provider 调用、零工具执行、一次回退；Sonnet 11 次 Provider 调用、一次搜索成功、三次原文读取失败；Opus 10 次 Provider 调用，搜索及原文读取成功，但引用的是 2014 年公告，仍未覆盖后续 3C/召回条件。不能从“工具已能使用”推出来源时效或 Q02 通过。

两个批次共 **48 条回复 / 53 次 Provider stream 调用**；各轮真实 usage、失败类型、延迟和唯一键已核对。没有设置 temperature、top_p 或 seed。最终三份完整第三轮 Python 程序经主代理检查后隔离执行，成功退出；该执行只覆盖展示的程序，不为全部解释或特殊异常行为背书。见[脱正文实测与校验和记录](runtime-source-smoke-evidence-2026-09-30.json)。完整原始文件保存在忽略目录 `.local/research/q02/`，公开记录不复制页面正文，且明确不将此轮单版本兼容性测试称为 A/B、独立盲评或人工验收。

独立实际搜索曾返回五个民航局域名结果，首条为旧公告；抓取时间和页面指纹只能证明取到了该页。官方域名、日期关键词、搜索成功或代码成功都不替代选定法规与技术事实的完整审计。后续需修复来源选择和更新查证，再完成十二场景、三重复、同批 A/B 和三种 presentation 的质量门槛。v5 继续是候选，默认 v4 未替换，PR 保持草稿。
