# Q02：合同位置 Runtime 对照与完整请求预算异常修复

本轮继续在 192.168.1.103 请求用户指定端点的 `gemini-3.8-flash-high`。搜索为隔离的 SearXNG 360/Yandex，读取为 Crawl4AI 0.9.3，公网工具使用 `dns_resolver=cloudflare`。没有使用 AGY、Jina、Claude，没有修改生产模型、persona、预算、数据库，也没有发送渠道消息。

合同位置仅增加默认关闭的隔离选项。实际对照没有证明它值得采用，Q02 继续未通过。这次落实的确定性修复是：Provider 包装后的完整请求超预算时，保留来源/执行结果，按已有事实状态给出明确失败答复；不再把该异常直接抛成整轮失败。

## 实现与检查范围

此前的[48 次位置对照](q02-contract-position-control-2026-10-04.md)支持继续验证，但不足以变更默认行为。`PromptCompiler(output_contract_position="pre_user")` 将 Runtime 自己构造的输出合同独立交给 `PromptCompilation.pre_user_system_prompt`，安全、时间、身份、状态、关系与计划保持原有内容。默认 `system` 的合并提示保持相同文字。

`ConversationService` 和评测器传递此字段；OpenAI-compatible adapter 在 context/history 后、最新用户消息前插入可信 system 消息。新增文字进入编译估算，新增消息及其封装进入完整 wire 的参考估算。没有删除旧来源或降低分项上限来满足原 7292 门槛。模型预算、独立裁剪与估算限制仍按 [ADR 0062](../../adr/0062-model-context-budget-configuration.md) 执行。

必需工具的初次操作决策暂时移除此输出合同，实际执行后恢复；可选工具决策、普通回答、工具后续轮和来源修订轮保留。权限、执行收据、generation fencing 与取消行为没有改成由模型文字控制。

评测器增加 `--output-contract-position system|pre_user`，默认 system；位置进入 resume identity，禁止混合续跑。最终评测器版本 1.28.0。Provider 记录增加非私密合同 hash 和 HTTP 状态整数；来源包装器溢出时保留数字预算报告，不记录密钥、请求头、错误正文或隐式推理。

## 两次预算失败分别发生在哪里

`instant_message/pre_user`：新增网页已成功读取，2601 字符、未截断的原文记录尚未进入下一次 Provider 请求；来源决策包装后的完整 mandatory 输入超预算。供应商没有收到这份新增资料，不能将后续未答归因于模型看完仍不会答。

`single_text/system`：此前来源已经进入 Provider，草稿已生成；加入可信修订指令及包装后的修订请求超预算，草稿没有被发布。这与检索失败或模型没有形成答案不同。

旧 Agent 仅在自己的预先 fit 位置捕获 InputBudgetExceeded。来源评测包装器会重建原生决策/工具历史并再次 fit，那个完整 wire guard 的异常不在原捕获范围内。修复让初次决策、工具后续轮、最终回答和来源修订的包装溢出走对应失败路径；未读来源仍未核实，完整结果不能 fit 时明确停止总结，修订不能 fit 时不发布草稿。未裁剪来源正文或执行参数，未扩窗口，未改其他异常与取消的语义。

来源尚有待读记录时，失败文字改为“仍有需要核查的来源原文未成功读取”，避免已有部分读取成功却声称原文全部未读。确定性回归通过真实估算产生包装溢出，覆盖初始、已执行结果、待读来源、最终回答及修订，不向底层 Provider 发送过限请求，也不重执行外部操作。

## v27：修复后的两个独立补测

从 v26 两个预算失败场景冻结第 1 轮的前文与状态，在修复后的隔离源码中只调度充电宝问题。仓库要求四轮夹具，最初单轮夹具被预检拒绝，没有 HTTP 调用；保留该记录后修正为四轮、`--max-requests 1`。退出 2 表示剩余三个夹具轮次被明确额度边界停止，不是本次目标答复失败。

两个补测的首次实际 payload 都与各自 v26 失败场景的首次 payload 完全相同。各六个实际 Provider 请求，各一个答复完成，总共两条答复；随后现场来源选择/读取和模型输出可以不同，不能把成功归为纯预算修复效应。这两次没有再次触发实际溢出，异常处理的证明来自受控回归，而不是宣称真实故障已复现且消失。见[补测审计](q02-runtime-contract-budget-guard-2026-10-04/guard-v27/focused-audit.json)。

## 主审边界与结果

先按原问题/标准审查初次 21 条隐藏位置标签的答复，冻结理由、回复 hash 和评分，再揭示映射。评审者是实现作者，已知整体故障背景，不是独立双盲。其余 45 条完成样本保留原文且未完成主审，不赋默认分，也不声明完整位置比较已通过。

九个可配对问题：pre_user 优先 2、system 优先 3、平手 4，没有重现一致优势。一个 system 旅行准备答复在没有来源时给出 20000mAh/100Wh，声称“确保符合交通安检规定”；这个安全合规保证没有证据支持。问候收口仍有未请求的休息建议，身份说明仍有泛化帮助邀请或旁支提问。旧公告读取成功的详细答复虽保留能量分支、3C/召回、室内活动内容和时长，仍没有交代后续适用性未完整核实。

逐条理由及冻结/揭示记录见[主审目录](q02-runtime-contract-budget-guard-2026-10-04/primary-review/initial-primary-judgments.json)。没有用局部 persona 分数或输入没超限替代质量判断，也没有将模型返回的 flash/control 标签当作权重或推理档已获确认。
