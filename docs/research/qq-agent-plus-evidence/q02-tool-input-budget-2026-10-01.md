# Q02 工具输入预算

2026-10-01。修复范围是已有 Agent 工具循环的完整输入预算：最初决策、缺调用纠正、读取后的后续决策，以及写操作或工具阶段结束后的最终请求。普通无工具对话的编译分配策略保持原路径，本切片不更换默认 persona、不扩大工具路由或权限、不增加 Provider、数据库或模型分类调用。

## 已复现的缺口

[先前实际来源复测](q02-source-query-guidance-2026-10-01.md)中，配置 context window 为 8192，一搜两读后的请求报告 8862 prompt tokens。编译预算只包含最初角色、上下文和历史；Agent 恢复完整角色后继续添加 schema、参数及结果，没有检查完整请求。此前 `PromptBudgetReport.used` 还用预算上限钳住估算值，且漏掉部分 wrapper 与摘要正文，不能作为实际投影用量证明。

## 本切片设计

`ConversationService` 从同一份冻结编译结果传入内部、版本为 1.0 的 `LlmInputBudget`；评测器走相同契约。8192 窗口沿用原编译输入额度 7292，其他配置沿用既有编译分配公式。它不读取执行中的新配置，不改变安全、身份、关系状态或受理时间。

每次工具 Provider 请求前估算所有文本、schema、参数、结果和消息开销；图片预留也明确标为估算。沿用约两字符一 token 的启发式，**不是任何模型的精确 tokenizer，也不保证供应商输入或最终总 token 的硬上限**。最终实测必须另列供应商返回的 usage，未知用量不补零。

输入超额时，先将未执行的模型前言替换为明确省略标记，再按最旧优先省略先前助手回复和更早用户轮次，保留当前用户请求及最后一条历史用户请求。历史在原位置替换，维持源上下文索引；记忆/context、完整角色与安全规则、图片、调用参数、原有有界工具结果及 provenance 均保留。不二次截断来源正文、不改正文指纹、不把省略伪装成完整原文。初始被引用的助手历史也按 schema 占用限制，明确标记省略。

带着 schema 仍无法容纳、但已有成功结果时，提前关闭工具阶段并尝试无工具最终请求，完整保留调用/结果配对。关闭指令保留“不再执行、当前任务、完整条件、引用、缺口和不承诺后续”的要求，移除已有工具政策覆盖的重复文字。关闭阶段不会再执行工具；原四次工具、六次 Provider、写后关闭、去重、撤权及当前 generation 围栏仍生效。若必需输入仍放不下，返回明确预算不足提示；已执行操作的状态留在工具记录中，不称其未执行或重新尝试写入。所有读取失败仍走原有诚实失败保护。

`LlmInputBudgetReport` 只含版本、估算数和省略索引，评测 journal 随实际请求记录；生产日志只有 generation ID 与数字。提示模板身份升级为 v5（不是 persona v5），评测器升级为 1.6.0，指纹含新预算实现；公开协议字段、数据库与生产用户配置不变。编译 `used` 改为真实组装文本的估算值，允许诚实显示超过预算。
