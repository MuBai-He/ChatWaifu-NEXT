## 修改前依据和实施方案

冻结回放先重建 v26 两个失败点的前一请求，实际发送 payload 逐字段一致。IM 新正文加入后完整参考 22832，省略旧助手消息后仍为 21852，超过 21370；单文本修订的完整参考 23452，Agent 省略历史后为 21296，但恢复原生决策历史的包装再次将其增至 22550。前者未发送新资料，后者未交付已有草稿，两类失败不能归为模型看完资料答错。

隔离试验使用 49152 操作窗口、8192 输出预留和请求 cap、15% 参考余量，参考输入额度 35617。13 次实际 HTTP、9 条完整回复均保持相应冻结原文。原额度下完整请求没有发出；不虚构一个低预算模型答复。单文本另以大额度发送原先省略旧助手的请求，单独比较历史有无。扩大额度恢复发送能力，但九条都没有明确说明旧媒体资料与原始规范/当前适用性缺口。不能据此提高生产默认预算。

进一步使用服务器现有隔离 SearXNG 查找后续原文。定向 `site:icao.int power banks 2026` 找到 ICAO 原始公告；Crawl4AI 读取失败，而内置 Reader 成功返回 HTML。内置默认 6000 字符仍在关键条款前截断，成功 HTTP 不代表模型获得了关键原文。国航 2026-08-04 的原始提示通过 Crawl4AI 成功读到，追加该真实资料的三条模型补测仍需独立审查。直接 Reader 对照与补充上下文不冒充 Runtime 技能收据。

据此，先实现一个默认关闭的 `crawl4ai_builtin_fallback`。仅当明确开启、选择 Crawl4AI、目标不是 PDF、且错误是服务不可用/网络失败/超时时，尝试一次原有内置 HTML/text Reader。两次尝试共享原 `read` 超时，保留解析/响应/地址/重定向限制和取消；认证、限流、安全验证错误不得触发。成功结果必须标明实际 `provider=builtin`、实际正文指纹/时间/摘录位置及原服务的非私密错误元数据。再次失败保留最终失败和首次错误的标量信息，不循环重试。

修改范围为读取 adapter、配置、web.read 可选输出元数据及版本、评测器 opt-in/resume identity、回归与操作文档。权限/确认仍走同一 Runtime Skill；不增加外部服务，不自动提高窗口、不裁剪来源事实、不改 persona/生产服务。先写失败回归，再实现并在服务器冻结源码下读取同一来源。该修复只解决可读取性，后续事实/角色质量继续按原完整 Q02 门槛验收。

## 来源发现与两段摘录

服务器隔离 SearXNG 的五条合法查询均成功，其中定向 ICAO 域的英文查询发现了原始公告；国航域查询没有找到目标提示。五次成功不证明引擎长期稳定，也不证明默认宽泛查询已经找到原文。首次诊断误设 `max_results=8`，超过允许的 5 条，五次均在参数检查阶段失败、没有搜索 HTTP；改为 5 后另开目录，错误证据没有删除。

真实 ICAO 公告介绍 2026-03-27 的新规范、每位旅客两块、禁止机上给充电宝再充电及机组运行例外；新闻公告与各国实际执行仍需区分。[ICAO 原始公告](https://www.icao.int/news/new-power-bank-restrictions-will-safeguard-international-aviation)

v29/v30 四次独立 Reader 对照均遇 Crawl4AI 502，经 opt-in 补救实际成功读取 builtin HTML；正常 Runtime Skill 两个批次各两次真实读取也走该路径。每次默认前 6000 字符止于关键条款之前；定位补读的偏移为 1173，取得后 6000 字符，包含数量、充电、生效和机组例外。结果仍如实 `truncated=true`，不能说一次摘录读完文档。每批两次 Runtime 摘录的同一指纹与区间并集覆盖全部 7173 字符**已提取文本**，这不是完整网站、链接目标或 Doc 9284 PDF 已读的证明。

## 后续诊断与两处范围修复

读取补救后的 v29 四轮提供链接试验只产生两条记录：第一条是 Runtime 回退、第二条是 Provider 回答；第三轮契约拒绝，第四轮未执行。保留九次真实请求，不能把两条记录都当作模型完整解答。第一轮虽补读关键段落，通用 `_source_quality_requirements` 因“公告/充电宝”套入国内综合要求，强制寻找本文没有的 3C、召回、Wh，误拦了指定文档概述。第三轮加载了真实历史正文，实验校验器却仅查当轮工具历史，报 `read_receipt_missing`。

依据这两个实际控制流缺陷，先声明修复方案再实施：对“明确 URL + 指定文档 + 不问现行适用性”的请求，免去**未请求的国内分项**，正常读取收据、权限和最终来源修订仍保留；复合问题包含当前/最新/是否仍生效等时保留原检查。该识别是有限语言规则，不是通用意图理解。确定性回归先出现 2 失败/3 通过，再验证指定文档实际读取及最终修订继续执行。

评测器校验加入 Runtime 提供的可信历史收据：必须同时匹配实际 skill_run_id、成功状态、完整正文数据，且这条正文确实保留在最终预算投影中，才进入已读集合。未提供可信 packet、篡改 ID/正文、metadata-only、不可用和预算省略均不计依据；开始新 generation 清空旧集合。历史阅读发生在新搜索之前，搜索后仍需读取候选原文。该修复只属于评测器，不能让模型库存声明变成生产事实许可。评测版本为 1.30.0，旧批次不混合续写。

v30 在新冻结源码/新目录重跑同一四轮输入：第一轮已交付日期、数量、充电和机组范围，第二轮准确说明本文没有 Wh 分档。指定链接的概述能力有所恢复；第一轮“提供给 193 成员国执行”的表述仍应准确区分公告分发与各国实际实施，直接主审记部分符合。第三轮的历史正文已识别，发起新搜索后 Provider 处理抛出 `RuntimeError`；第三轮未完成、第四轮未执行。八次真实 HTTP 中有一条 usage/identity 未知，保留未知而非记零。

针对最后一条**完全相同 payload**另做一次不执行工具的 SSE 重放。HTTP 200、原生函数和 JSON 校验成功，未复现错误；原失败没有保留完整 SSE，因此细原因仍未证明，不能断言是供应商格式、DNS 或额度。该重放不是原场景第三/四轮恢复。Runtime 原始正文只在该服务进程中保留；进程退出后，仅恢复旧助手文字或 redacted DB 不能构成等价续跑。本轮没有据此伪造恢复的阅读收据或重跑已完成轮次。

v29 输入/completion/total 为 71402/2835/80695（9/9 已报），reasoning 8/9 已知小计 6458；v30 三项 7/8 已知小计 51311/1499/55432，reasoning 5/8 已知小计 2622。不能将 partial subtotal 称为全部花费。完整 wire 参考误差分别为 +0.2118% 至 +10.4404%、+0.2118% 至 +14.7416%，量纲与中文旧资料不同。逐次真实 payload、供应商标签、结果/失败、延迟、正文位置及未知用量见[Runtime 审计](q02-frozen-budget-source-scope-2026-10-04/runtime/runtime-accounting-audit.json)。原始重放 usage 单独列出，不与未知失败次数相抵扣。
