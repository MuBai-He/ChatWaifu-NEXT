## 故障依据与修改

对指定群的只读日志、数据库和 OneBot 历史核对发现：20:18:48 的真实纯 @ 没有创建轮次，旧 normalizer 拒绝空正文。20:18:12 的“你怎么看”注入四条文字、无裁剪，却回复“连图都没有”。较新的日期追问注入七条原文且投递完成，说明需要区分通路工作和回答承接。

组装缺陷可以确定复现：group discussion 位于普通 context，Provider 将 context 放在正式 history 前。因此较新的旁听资料出现在旧“没有图片”回答之前。源码回归在修复前六项失败；其中 actual Runtime/OneBot fixture 的最新问题前一条 wire 消息确为旧“什么都没有”，而非新讨论。该排布提供了错误时间顺序，但仅凭现有证据不能认定它是当晚原回复的唯一原因。

现在内部 `LlmRequest.current_turn_evidence` 保持最近资料为不可信 user-role 消息，置于旧历史之后、可信输出约束和当前问题之前。旧历史、原文、角色规则及预算不改；完整 wire 估算包含此字段，其他入口默认空字段。

纯 @ 使用 transport 的明确 `mention_only` 标记，仍需真实单次机器人 mention、启用路由和原 `can_speak` 授权。正式轮次记录 `[仅 @ 角色]`，只在模型投影里表达“接着最近话题”；无资料、失效、旁听关闭或没有注入空间时表达“请问我想聊什么”。不解析用户文字来设置标记，不把标记加入旁听或记忆提取，也不因纯 @ 偷带此前图片。消息去重、成员围栏、取消、群聊纯文字规则保留。默认缓存/摘要阈值保持 ADR 0075，不增加新的模型窗口或提示分项压缩。

[预算观测](budget-observations.json)：当前配置仍为 operational window 65536、输出预留 900、margin 0，输入 allowance 64636；没有探测供应商原生最大窗口。A/B 两种完整请求均为 3566 参考 token，供应商 prompt usage 均为 2903，资料均保留四条，无摘要/省略。该材料原生用量比参考低约 18.6%，不构成通用误差上界。首批旧排布耗时 4.3–5.6 秒，新排布 6.5–8.4 秒；补充为旧 7.0 秒/新 4.6 秒，不宣称延迟改善或生产 p95。

首批九条均捕获真实 transport JSON 和归一化供应商 usage；raw SSE usage 采集最初接错了 aiter_lines，而当前 Provider 使用自己的 bytes SSE 迭代器。保留九条原样记录，另只补充一对请求以验证 [原始 usage](model-usage-supplement.json)，没有覆盖或整批重跑。该流式端点 raw completion_tokens 不含单列 reasoning，而 total_tokens 包含它，按原字段记录；这与先前非流式摘要用量的表达方式不同，不能重复相加。
