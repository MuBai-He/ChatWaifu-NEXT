# Q02：来源范围、片段覆盖与后置查新对照

继续使用服务器 Gemini 3.8 Flash High 与 SearXNG/Crawl4AI，公网读取使用 Cloudflare DNS。
本轮从 v21 实际请求冻结问题、历史与原始工具资料进行对照，没有重新发送渠道消息。
Q02 仍未通过；结构、来源取得与最终质量分别判断。

## 修改前依据与决定

- 补充发布角色字段能促使模型选择搜索，但最初改函数名与旧原生历史冲突：三次仅一次名称正确。
  保持名称并明确追溯范围后，三次结构及 URL 归属均通过；查询仍围绕旧 3C 基础要求。
- 摘录正文署名没有解决追溯：三次中一次直接结束，两次仍搜通用旧要求。
  实际执行前组与本组的五条查询，均有返回，但没有找到这篇 2026 年报道的原始发布。
- 保留全部非 system 对话/工具原文，只替换为简明来源决策指令的对照未稳定改善：
  法规三次均想直接结束，其中两次 schema 错误；Raft 三次仅一次提出补读，另外两次仍添未核实细节。
  不采用这项精简，不把减少输入当成质量提升。
- 独立读取同一 Raft 原论文 5.2 节，再加入相同最终修订请求，提供了原先 5.6 片段中缺失的
  150–300ms 示例依据；输入增加 1595 个供应商 token。原组与补充组三次都引用该数值，
  补充组仍出现未经资料支持的工程概括，不能宣布更大输入已经解决质量问题。
- 冻结法规读后请求，仅把下一动作约束为查新搜索并补充流程说明，三次都输出新的、不预填固定
  权威域名或阈值的查询。该结果仅支持实施一个可检查的流程约束，不证明查询质量或最终回答通过。

## 选定的最小实现切片

仅修改 opt-in 的开发评估来源适配器，生产 Runtime 保持 v17，不修改生产配置或模型输入上限。

1. 原生契约新增模型声明的 `verification_scope`：现行要求、技术解释、指定内容或其他。
   它是任务意图假设，不是事实认证，不新增模型分类请求，不解析任意自然语言操控状态。
2. 仅当模型已声明现行要求、实际收据有成功正文读取、之后尚未尝试搜索、没有已知可读的待核实线索，且至少还有两次调用额度及搜索能力时，
   下一次来源动作限定为搜索。保留完整问题、角色、安全及来源资料；不采用上面的精简提示。
3. 只检查实际收据顺序；前置搜索、读失败、没有正文均不能冒充读后查新。
   后置搜索失败/拒绝记为已尝试，不强制无限重试；最终无工具回合始终无工具。
4. 仍是六次来源调用、最多一次契约纠正、现有权限与取消边界。优先读取已知待核实来源，为新搜索保留一次后续读取额度。不提供固定查询、参考答案或新 URL。
   搜索完成不自动说明资料完整；原先搜索后须读正文的 Runtime 约束与最终答复审查继续生效。
5. 契约升版并记录真实模型声明、流程状态、原生到实际技能映射。补确定性测试，冻结服务器快照，
   先重跑两条四轮场景；逐条核对最终事实、出处范围与实际输入，再决定是否用于完整 Q02 评估。

这项切片没有解决模型漏判任务意图、搜索词不佳、来源权威性误判或工程断言的全部问题。
不得据此缩减完整十二场景、三重复、A/B、三种 presentation 和盲评门槛。

原始对照请求、响应、实际 Reader/搜索控制与脚本在
[对照证据目录](q02-source-scope-excerpt-controls-2026-10-03/)。这些 non-stream 探针和独立适配器控制
不属于 Runtime Skill 权限执行或真实渠道验收，后续真实八轮单独记录。

## 实施与真实执行结果

已按上述方案落地隔离契约 v4（精确函数名 `cw2_source_decision_v4`），评估器版本
`1.24.1`。模型的范围声明只在有效原生结构和 URL 归属通过后生效，当前要求标记在本轮内保留，
下轮 `begin()` 重置；实际查询仍走现有 Runtime Gateway。模型声明、查询动作投影、真实 SkillRun
和后续原生历史分别保留。最终无工具回合保持无工具，并在没有读后搜索收据时明确提供流程缺口。

独立审查复现了 v22 的两个问题：额外查新挤占已知待读线索，以及只余一次调用时要求搜索导致
没有后续读取机会。新增回归在 v22 均失败，v23 修复后通过。修复不扩大六次来源调用或一次
契约纠正额度。失败日志、两版真实请求和冻结源码分别保留，未覆盖 v22。

| 真实批次 | 完成逻辑轮次 | 实际 HTTP | 成功搜索 / 读取 | prompt / 正文 completion / total | p50 / p95 ms |
| -------- | -----------: | --------: | --------------: | -------------------------------- | ------------ |
| v22      |          8/8 |        19 |           3 / 3 | 131074 / 6439 / 148622           | 7844 / 87343 |
| v23      |          8/8 |        21 |           4 / 4 | 191250 / 8972 / 209039           | 7048 / 66032 |

这里 Runtime 的正文 completion 已拆出 reasoning，与前述探针的原始 completion 口径不同。
v22/v23 reasoning 分别只有 15/19、15/21 次显式报告，已知小计 11109/8817，缺失不补零。
本轮包括探针与两个真实批次合计 **70 次请求、624293 total tokens**；不计算未经证实的美元费用。
各组样本小、未设 seed，不能把单次延迟差解释为稳定收益。

两批都使用同一问题、候选 persona v7、single_text、一次重复、32768 窗口、8192 输出预留、15%
估算余量、相同时间参考及服务器服务；它们是小范围调试，不是完整 A/B 或三展示验收。
两批均无 history/tool preamble 预算省略；参考估算误差分别为 -0.90%～+36.13%、
-3.59%～+36.13%。v23 原论文两次各保留 6000 字符，其余部分仍未进入该次 read 结果。
**输入没超限既不说明所有文档都已提供，也不说明回答正确。**

逐条[非盲审 v22](q02-source-scope-excerpt-controls-2026-10-03/runtime-v22/primary-review.json)与
[非盲审 v23](q02-source-scope-excerpt-controls-2026-10-03/runtime-v23/primary-review.json)的主要发现：

- v22 法规回合确实读后查新，五条结果包含春秋航空变更通知，但模型没列入待核实清单、仍试图结束。
  一次普通文本违反原生契约被拒后，纠正仍结束，最后 Runtime 回退；因此 8 条终态中只有 7 条来自
  Provider，三条规则任务未完成。不能将“8/8 完成运行”当作八条任务完成。
- v23 法规查新后读到了 2025 新闻，最终 8 条均来自 Provider；但仍只依据 2015 指南和 2025 新闻，
  未核对检索中出现的 2026 线索，也没有披露现行范围缺口。选定 3C/召回关键词审计通过，**质量不通过**。
- v23 Raft 实际读了 5.6 和 5.2，150–300ms 示例有正文依据，避免了 v22 对所有重置都重新随机的概括；
  仍有固定心跳间隔和“任何通信”之类范围过宽的描述，不能提升为规范统一要求。
- 两版详细清单保留类别、数量、两套备选活动及用时，但一般出行建议还会添无来源的交通容量限制；
  v22 闲聊出现没有视觉输入却称“你这么看着我”，v23 闲聊长度仍偏长。这些是完整 Q02 的问题，
  不因来源管线改善而忽略。

原生调用到实际技能收据的映射审计、八条机械展示检查在两批均通过；它们不验证发布者语义或事实。
v23 本地/服务器定向检查各 **106 通过**，完整 Python **2142 通过、46 个平台相关跳过**，
全量 Pyright、改动文件 Ruff/格式、Web build 与 diff 检查通过。没有把已跑过的真实微信、
播放 ACK 和用户听到证据重新发送一遍。47 个原始探针/运行文件已在服务器检查配置密钥缺席、
复制后核对 SHA256；生成审计与测试日志另有目录清单。

## 仍需完成的验收工作

当前实现仍是 opt-in 评估器候选，生产 Runtime、persona、模型路由、预算和数据库没有改变。
未采用发布者字段、摘录署名或精简系统提示作为事实认证，也未启用 AGY、Jina 或其他模型。

下一步优先处理**模型漏列线索后，原生契约仍允许与 Runtime 待读门禁冲突的结束决定**：
复用实际搜索/读取收据顺序约束下一步动作，失败、拒绝、无可读线索和预算耗尽保留诚实退出，
避免只增加自然语言提醒或无限重试。该流程修复仍不能代替查询质量、原始依据、后续更新和技术
断言的逐条核查。小范围质量改善后，仍须回到十二场景、三次重复、A/B、三种 presentation 的
完整评测和盲审；Q02 目标继续开放，不缩为“来源工具能运行”。
