## 行为和默认值

普通群文字经当前账号、连接、启用路由和已授权成员检查后，进入短期内存缓存，不创建轮次、模型请求、正式历史或记忆来源。当前受众中已启用链接的成员可以贡献讨论；只有已有 `can_speak` 授权及真实 @ 才触发回答。不会通过昵称或模型输出增权。

| 限制 | 默认值 |
| --- | --- |
| 每条缓存原文 | 800 字，截断量可见；当前问题保留既有入站/完整请求检查 |
| 每群 | 96 条、24000 字、15 分钟 |
| 每成员 | 24 条、6000 字；再受群总量÷受众人数的公平上限约束 |
| 频率与重复 | 每成员 30 秒 6 条；同内容 60 秒去重；消息 ID 去重有界且不续期 |
| 缓存群数量 | 32；不挤掉另一群的活跃缓存 |
| 未 @ 待接纳任务 | 总计最多 24，同成员/群最多 3；所有群接纳任务仍最多 32 |
| 旁听模型份额 | 最多 1536 参考 token，同时不超过 chat 输入 allowance 的 1/4 和完整请求剩余空间 |
| 原文/较早摘要 | 优先最近原文；压缩时原文份额 75%，较早摘录最多 25% |
| 摘要调用 | 有效 @ 且资料超预算时最多一次；输入最多 3072 参考 token，输出请求最多 256 token，8 秒超时；同时服从摘要路由的输入限制、输出预留与输出上限 |

Operator 配置位于 `[group_discussion]` 或 `CHATWAIFU_GROUP_DISCUSSION__...`；读取后的 policy 不可变，变更后重启会清空缓存并沿用原群重新授权。`config/default.toml` 给出完整示例。没有新增数据库迁移或前端管理入口。

较早摘要为可追溯的**摘录选择**：模型只能返回原消息 ID；Runtime 按原顺序复制被选中的原文、可信 participant ID、接收时间和来源 ID。未知/重复 ID、额外生成文字、超预算、漏掉摘要输入里的一方发言者均拒绝该摘要。失败或超时使用完整份额内的最近原文；取消传播，不把撤权当作摘要失败降级。该机制防止摘要补造文字，但仍可能漏选关键信息，最终回答也仍可能作未标出的推断。

快照按账号、连接 revision、群、route revision、scene 和 audience fingerprint 隔离。成员/链接变化、群关闭、账号切换、重连和 reset 清除缓存并围栏在途工作。摘要只存活于当前 generation；不从正式历史重建旁听缓存。正式 @ 问题仍经过原场景/发言者/subject 的记忆准入，缓存原文与摘要不送入提取。私聊历史、私聊记忆和私人图片不进入群旁听。

按本次要求，群投递只允许文字，包含最终发送授权；此前可选群表情输出现已关闭。群内图片理解/学习仍按原 opt-in 范围工作，私聊表情和按需语音保持原行为。

## 冻结真实模型检查

模型保持 `gemini-3.8-flash-high`，使用服务器当前 8318 端点。材料全部是自建测试讨论，没有生产群/私聊原文。短讨论来自真实 Runtime fixture 最终送给模型的请求；长讨论使用生产同一 projector 和冻结的两人方案/分歧资料。每种两次实际 Gemini 生成，总计四条最终样本，另有一次真实摘录请求。没有 QQ 发送。

[最终 payload、原回复、usage 和延迟](model-final.json) 保留全部证据。短讨论原文三条均保留，不调用摘要；长讨论 25 条中保留最近 13 条及较早两条关键原文（ID 1/2），省略 ID 3–12 的十条无新结论补充。摘要实际选择 `1/2`，没有改写事实、顺序、发言者或来源。

| 检查 | 审查结论 |
| --- | --- |
| 短讨论指代承接 | 两条回复均围绕本地/数据安全及维护人选，承接了“这个选择” |
| 较早关键事实 | 两条长回复保留 A 每月 20 元/快/上传资料，B 免费/本地/维护人选未定 |

| 严格观点/未决问题保真 | **未通过**：两条长回复把 Bob “提到 B”推断成“更倾向 B”，未标出推断；一条仍新增了原消息没有明确提出的“接受哪一方妥协”问题 |
| 取消/权限/手机显示 | 由源码用例及另列手机验收验证，不能靠上述内容判断 |
