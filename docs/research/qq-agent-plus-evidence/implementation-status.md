Q06 补充了针对检索层的真实离线量化评估（`tools/evaluate_memory_retrieval.py` 与 `tests/fixtures/memory/retrieval_scenarios.json`），使用真实 `MemoryRetriever` 和临时 `SQLiteMemoryRepository`，以事件为源头灌入合成数据，覆盖 10 组设计条件（9 组检索可评估，1 组来源缺失由写入边界验证）：

1. **明确事实、待确认隐含事实、敏感事实、过时事实、删除、重启**：这些合成场景未出现错误召回（FP=0），敏感事实与未确认提案不泄露，Tombstone 与 Superseded 事实在重启后依旧被可靠排除。
2. **来源缺失边界**：`MemoryRetriever` 假定库内记录已有合法来源；来源校验在仓储写入时强行校验（`create_record` 缺少 sources 抛 `ValueError`），评估器诚实将此记录为写入契约硬约束，未伪称检索层过滤。
3. **真实非零误召回与遗漏**：
   - 预算压力场景：在 25 tokens 紧缩预算下，4 条相关生活习惯仅容纳 1 条（16 tokens），测得真实遗漏 FN=3（遗漏率 75.0%）。
   - 共同梗场景：查询含“记得”触发显式回忆补齐，FTS 候选不足 3 条时回退补充最近记录，拉入非梗甜品偏好，测得 FP=1（误召回率 50%）。
   - 纠错场景：针对旧偏好的探测词命中更正后的记录；这条记录能纠正错误前提，标为相关命中，旧 Rust 记录仍不可召回。
4. **定向测试与检查**：新增 `tools/tests/test_evaluate_memory_retrieval.py`（15 个测试用例全部通过，Ruff 与 Pyright 0 警告 0 报错），`--check` 参数确保敏感、过时与删除记录不得出现在检索结果，并检查合成基线指标。
