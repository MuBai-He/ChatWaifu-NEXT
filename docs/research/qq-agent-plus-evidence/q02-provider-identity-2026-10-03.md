# Q02：记录供应商实际返回的模型标识

## 修改前依据与方案

v24 后的真实 non-stream 对照始终请求 `gemini-3.8-flash-high`，但返回 `model`
交替为 `gemini-3.8-flash` 与 `gemini-3.8-flash-control`。反向顺序对照已保存，不能
根据别名猜测底层权重或推理档位。现有流式 Adapter 丢掉此字段，评测只记配置名，
因此完整 A/B 无法检查这个混杂因素。

本切片仅补观察证据：在 Provider 完成事件增加可选、带版本的响应标识元数据，记录
响应实际提供的不同模型标签。最多八项、每项最多 256 个可打印字符；异常、超长或
超过上限明确标记不完整。缺报保持未知，不用请求的模型名回填，不推断底层模型身份。

标准流终止、usage 尾块、HTTP EOF 和不请求 usage 的提前结束路径均保留该信息；
每次请求独立，不改变正文、工具调用、usage、取消或重试行为。评测保存每次 Provider
完成事件的元数据，普通直连与真实 Runtime 工具路径均覆盖；失败样本保留已获得的元数据。
不新增生产数据库字段、模型路由、预算或用户可见提示，不升级成事实/角色质量通过门槛。

先用 SSE 及评测回归复现缺失，再实施、检查类型和相关生命周期测试；随后在服务器
冻结快照实测同一端点的真实流式请求。原始来源决策与八轮质量门槛仍沿用 v24，
身份字段本身不解决来源现行性、技术正确性或完整三展示配对质量验收。

## 已完成的实现与验证

`LlmResponseIdentity` 版本 1.0 通过 `LlmResponseCompleted.identity` 传递实际标签；
配置模型名独立保留。来源评测的每个 Provider 回合记录 `response_identity`，普通与
Runtime 评测样本记录 `provider_response_identities`。续读旧数据时缺失字段仍是未知，
工具版本升为 1.26.0；不把不同 schema 的批次悄悄拼接续跑。

六条 SSE 回归在旧代码失败；新增检查覆盖 DONE、HTTP EOF、不请求 usage 的结束、
usage 尾块、原生工具结束、坏标签/数量上限、同一 Provider 跨请求隔离，以及两种
评测路径的正常/空答失败记录。完成事件前断流而未交出身份数据时仍记为未知。
本地和服务器定向各 132 通过，全量 Python 2159 通过、46 平台相关跳过；Pyright、
Ruff 和格式通过。审查以服务器 v24/v25 冻结源码的实际 diff 为准，保留先前工作树改动。
这次没有前端或共享对外协议改动，未部署生产。

服务器真实四次流式请求按 `request_usage=[true,false,false,true]` 执行，同一问题与
请求模型不变。Adapter 和评测 journal 中的标签四次都与独立观察到的 SSE `model`
字段一致，返回标签确实交替为 `gemini-3.8-flash-control` 与 `gemini-3.8-flash`。
这证明标签被保留，仍不能证明它们对应不同权重或指定 High 推理档位。

四次延迟 3806/3806/3500/3621ms。只在两次请求 usage 的调用中取得用量，已知
prompt 40、正文 completion 50、reasoning 843、total 933；不能把另外两次记零，
因此这不是整批用量或 Q02 质量测试。实际请求、SSE 模型字段、终态、journal、冻结源码与
检查日志在[身份记录证据](q02-provider-identity-2026-10-03/)。十九个远端原始文件及源码
复制后 hash 匹配，配置的模型/Reader 凭据扫描无命中。

## SearXNG 其他上游的调查

隔离 18082 实例沿用既有代理和镜像，尝试 Baidu、Yahoo、Qwant、Mojeek、Startpage、
Bing News。实际完成十二个 HTTP 请求，其中两个请求不能作为所声称引擎的证据：
镜像默认把 Mojeek/Startpage 标为 inactive，`/config` 中未启用；传入这些名称后
服务回落到混合搜索，返回的是 Yahoo，且再次出现此前验证码上游的错误。
没有绕过验证码、轮换代理或把这些行算作成功。

其余观察：Baidu/Qwant 首次直查为验证码；Yahoo 四条查询三条非空，取得较新二手
报道和 Raft 官方首页，但带年份的航司泛查询为空；Bing News 两条解析错误，其余
结果混有旧新闻和其他司法辖区。模块文件存在、`/healthz` 正常、返回非空都不能证明
目标引擎在工作。完整结果、active/inactive 标记和无效行见
[上游证据](q02-provider-identity-2026-10-03/additional-engines/)。

Yahoo 有新增来源覆盖，随后进行了一次真实任务筛选。隔离候选仅保留
360search、Yandex、Yahoo，并在发查询前强制核对 `/config` 恰好启用这三项。
同一 Gemini、persona、预算、问题与来源契约重跑两条四轮场景，判断最终选择和回答，
不按搜索计数通过。生产 18080 与原候选 18081 保持不变，读取仍使用 Crawl4AI/Cloudflare。

与 v24 的差别归因于 Yahoo。十九次实际响应标签均有记录，同一回复的多次调用中
也出现 flash/control 混合，标签含义仍未确认。

逐轮主代理直接复核（未隐藏版本）见 [review.json](q02-provider-identity-2026-10-03/runtime/review.json)。
机械展示保全和旧事实关键词审计均通过，但最终质量仍未通过：

- Raft 实际读取了论文时序约束及随机选举片段，150–300ms 示例有原文支持；
  “每次合法心跳都重新随机生成超时”仍被写成普遍规则，原文片段不支持这个概括。
- 法规实际读到 2014 公告的转载及 2025 新闻综述，Wh 换算式确实在已读正文，
  不能误报为凭空增加。回复未说明转载身份、资料日期和当前有效性缺口，且沿用了
  新闻中较窄的“市场监管总局召回”表述；该新闻前后对数量/召回的描述本身也不同。
  这同时涉及搜索未发现更新、二手材料可信度与最终回答未保持来源范围。
- 雨天清单保住两项活动的时长，但把活动内容压成场所名和注意事项；没有完整保留
  阅读/茶饮/整理照片等建议。清单又把上一轮的旧规则写成当前民航规定，未保留来源局限。
