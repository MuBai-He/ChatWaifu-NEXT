# ADR 0085: One owner Agent for observation, memory and durable action

Status: Accepted for source implementation by the owner on 2026-10-31. Production enablement and real-provider/device acceptance are separate gates.

## Decision

Extend the existing Runtime, AgentTurnOrchestrator, AgentTaskService, MemoryService and RuntimeSkillService. Do not introduce a second Agent server, workflow engine or authority store. Chat and durable tasks use explicit execution lineage and the same permissioned tool loop. Information extraction is a bounded sub-workflow; the legacy information endpoint remains proposal-only.

Runtime owns AI extraction and continuous execution. Android retains collection, raw-source storage, offline edits, synchronized projections and device reminders. Processing ownership transfers through prepare/checkpoint/drain/activate epochs. Completed exact source versions and pending reviews migrate without rewriting confirmed records. Legacy analysis is fenced once a source moves to Runtime. Version 1.0 sync remains accepted; negotiated 1.1 sync carries ingestion mode and processing epoch.

SQLite migration 49 adds standing intents, processing ownership, an observation outbox, canonical work items, dispatch identities, progress receipts, activity and delivery receipts. Source ingestion and observation enqueue commit together. Observation consumers are bounded and prioritized; history does not authorize retrospective action. Android schema 6 adds only durable processing and delivery acknowledgements.

A standing intent is owner authority, distinct from source content and from a single run. It binds source rooms, reviewed execution modes, capability fingerprints, selected calendar/list resources, allowed operations and bounded run budgets. It persists until revoked or explicitly expired. Pausing/revoking invalidates subsequent effects. Existing explicit tasks retain their authorization semantics. Discovery never grants permission.

Shared recall returns typed, exact-version knowledge evidence alongside formal memory. It does not synthesize chat evidence from imported material. Grounded, nonsensitive, unconflicted low-risk facts may be accepted under a recorded policy; other candidates remain in review. Human confirmation is distinguishable from policy acceptance. Correction, rejection, exclusion and forgetting take precedence over re-extraction. Forgetting also redacts derived work, task continuations, step results and activity; late results cannot repopulate them.

WorkItem provides logical identity and source lineage; provider bindings identify the actual external object. Google/Apple remain authoritative for their native objects. The existing knowledge channel projects accepted work to Android and accepts version-checked offline edits. A proposed change cannot silently overwrite a confirmed item. Calendar operations support normal events and individual recurring instances; masters and whole-series rewrites remain unsupported.

Side effects receive a stable Runtime-issued action ID. Google calendar writes are read back and checked for identity, dates and instance lineage. Completion verification requires provider facts. Interrupted known-ID operations may be reconciled using provider reads; an ambiguous outcome is not replayed. Readback evidence is recorded as readback, not fabricated as an original write acknowledgement.

Source-conditioned waits and timed wakes stay in AgentTaskService. New relevant evidence resumes an existing goal within the current standing authority. Closing the chat does not cancel that goal. Web, desktop and Android display the same standing intents, reviews and activity. Important changes are delivered separately from execution; accepted, presented, opened, blocked and unknown delivery are distinct facts.

## Compatibility and rollout

Append migrations; do not rewrite previously applied scripts. Keep old proposal APIs and negotiate ownership before retiring native extraction. Preserve original IDs, exclusions, forgotten-source fences and confirmed content. Verify source snapshots and immutable operation identities before integration. Roll out synthetic checks, shadow decisions, a dedicated test calendar, then explicitly selected real sources. Rollback stops dispatch and preserves the action ledger; restoring a database is not a rollback of remote effects.

The detailed design and user choices are recorded in [the implementation plan](../plans/unified-agent-harness-proposal-2026-10-31.md). Validation is tracked in [the verification record](../operations/unified-agent-harness-validation-2026-10-31.md).

## Implementation details and release boundary

The Runtime owns the observation workers, per-intent recheck cursors and task wakeups. These are input-consumer checkpoints; AgentTaskService remains the only goal state machine. Enabling or resuming a delegation rechecks current, unhandled live/delayed work. Historical backfill never obtains action authority through that recheck. Decision results are checked against the current intent revision again before creating work.

The persistent observation journal grows with the source archive. It stores references and processing metadata, not a second copy of message bodies. Bounded leases, coalesced batches, three observation workers and per-route model admission limit runnable work. Historical journal depth cannot reject an otherwise valid live source transaction. New source revisions invalidate a coalesced model result; unaffected neighbors return to the queue instead of being acknowledged as processed.

Accepted external facts retain real knowledge-record identities and confirmation provenance. Existing event-backed formal memory remains event-backed. MemoryService supplies the common deterministic admission/identity policy and the shared retrieval packet; owner correction, conflict review and exact forgetting cross these stores through domain ports. No WeChat fact is given a fabricated conversation event. Manually corrected facts carry human acceptance and a new structured identity, and older values cannot be reintroduced by replay.

Google action proposals are immutable, versioned journal data, with work/source/authorization revisions, stable action IDs, the target and verification requirements. Freeform titles and details use hashes in action metadata; source and result provenance remain available through their owning stores. Per-work journal claims serialize different operations as well as deduplicating identical actions. A lost Google Tasks creation reply does not establish which newly observed task belongs to that request: it stays outcome_unknown for owner review and is never blindly replayed.

Ordinary timed and all-day Google events are supported. All-day end dates are exclusive and do not acquire an invented clock time. Recurring exceptions retain series and original-occurrence identity after a move or cancellation. Entire-series/following edits remain unsupported. Date-only Google Tasks due dates and precise local reminder times remain separate fields.

Future reminder arrangement requires a primary-device download receipt. A due reminder goal requires presentation evidence; a blocked or unknown presentation is not completion. Accepted, presented, opened and human confirmation are distinct facts. Android's visible remote-messaging connection receives Runtime updates; it performs no AI. OEM background lifetime and real presentation still require handset acceptance. Service-type rationale: [Android remote messaging foreground services](https://developer.android.com/develop/background-work/services/fgs/service-types#remote-messaging).

Protocol 1.0 source collectors remain data collectors after handoff; Runtime observes their accepted source changes using conservative legacy timing. Protocol 1.1 adds per-source capture metadata to distinguish explicit backfill from offline delivery. Legacy analysis remains suggestion-only and cannot reclaim a migrated source. Native edits to externally bound items use WorkItem commands; old direct knowledge edits enter conflict review and cannot become a competing external-state writer.

Source verification does not establish production or model-quality acceptance. Use CW2's own selected account and a dedicated test calendar, then run the fixed six-scene dataset at least three times per scene. Do not substitute model self-assessment for provider, artifact or device receipts. The source-only phase did not modify credentials, production databases or real calendar objects. Later owner-authorized acceptance created disposable objects in dedicated Google resources; the main production database remains v48 and the full harness runs in an isolated v49 acceptance Runtime. Actual-provider and device evidence, failed attempts and remaining release gates are recorded in the verification ledger.

Successful execution settling a ready event/todo from waiting to open, or updating only its reconciliation cursor/accounting, does not advance its business revision when target identity, verified binding, source basis, dates, reminder and acceptance are unchanged. These progress updates remain observable through task/activity state. Actual business changes and owner decisions still advance the revision and retain CAS checks, so an internal projection cannot invalidate an already-issued proposal.

A durable task's knowledge epoch fence raises a typed context-change signal. The task drops its old packet, rechecks authority and builds the latest owner/audience context within its existing budget. Settled writes go to independent completion/domain verification before any further execution; unknown outcomes remain waiting for reconciliation. Repeated invalidation defers the same task through the existing timer, without adding another task state machine. A knowledge refresh cannot bypass revocation, exact source eligibility or forgetting.


Android's owner-enabled timely connection also drains the existing native source/edit/control outboxes. Collector signals and reconnects coalesce into one bounded sync request; known backlog proceeds through bounded cycles without an idle long poll between them. JobScheduler remains the durable fallback. A transfer may hold a partial wake lock for at most 120 seconds, released on completion; no model inference or provider credentials move to the phone. Once Runtime owns processing, the legacy AI intake does not grow a second queue. Local exclusion/confirmed-state capture is transactional, unchanged scope metadata is skipped, and changed exclusion decisions retain the same outbound revisions and server checks.

A provider exhausting native-tool protocol repair enters independent completion verification even when tool budget remains. Verified facts may close the goal; otherwise the existing bounded repair loop uses the remaining grant and budgets. Unknown effects do not enter this fallback. A context change during domain readback is fenced again before a terminal checkpoint.


Unconfirmed work carries a conservative temporal assessment separate from its business state and acceptance. The trusted current evaluation time never replaces the original message time for relative-date interpretation. Historical or uncertain work cannot obtain automatic action through intent rechecks; current evidence or explicit human review is required. The existing seven-day recent-intake window is a review boundary only: future arrangements and confirmed overdue work are preserved, and age does not prove completion. Native legacy reviews derive the same placement without rewriting original records, with individual current-relevance confirmation and a fresh bulk-commit guard.

## 2026-11-01 follow-through and bounded understanding

A fresh owner confirmation is a durable, idempotent command distinct from a historical import. Its owner decision does not rewrite the source's ingestion mode. Android commits the command with the local confirmation; Runtime continues through AgentTaskService only inside an existing standing grant. Missing authority or evidence remains visible as blocked work. The current registry's execution modes are checked again before task execution, including after a capability changes without a version increment; legacy `background_allowed` behavior is retained.

Information understanding has an internal version 1.0 profile sharing the legacy parser, owner admission, source validation and temporal policy. Ordinary inputs still require one extraction pass. A structured missing-fact request may perform at most three read-only knowledge queries and one further understanding pass within 300 seconds. Context is bounded to 6,000 characters and ten entries, also reserving the existing 30-evidence limit. Queries use the common knowledge retrieval service; slow graph lookup falls back to authoritative keyword records. Sources are revalidated around asynchronous boundaries. These context lookups grant no tools or write authority and introduce no additional task state machine. Public analysis 1.1/1.2 continues to return proposals only.

Optional reminder defaults belong to a versioned standing intent and an owner-selected registered device. They apply to future new work; explicit source reminders and an explicit refusal take precedence. Conflicting scoped defaults wait for review. A date-only deadline never supplies a guessed clock time. Default rules retain a relative offset when work moves. A standing task cannot override an explicit refusal by setting a reminder through an edit tool.

Native schema 8 adds indexes over existing structured source and queue columns. It does not rely on optional Android SQLite JSON functions or rewrite message content. Handoff pages cover one conversation and only current source versions whose every segment is done; they reconstruct the full original text rather than treating a completed first segment as completion of the entire message. Exact acknowledgements and per-source/epoch cursors survive interruption. Missing originals enter the normal source sync outbox; newer originals are never marked handled using an older native analysis.


## 2026-11-04 owner-requested review expiry

Unconfirmed create/update proposals with an explicit elapsed deadline or event end move to historical review even when their original message is recent. This is review placement, not completion, deletion, or cancellation. Confirmed overdue work, durable facts and future arrangements retain their prior semantics. Date-only deadlines use the item's local day boundary. Android's cached partitions and Runtime's pending-work metadata refresh from the clock without model calls; fresh writes recheck expiry, while prior effects still require readback. The owner requested this behavior after observing unconfirmed summaries remaining current on the following day.

## 2026-11-04 provider wake and measured operations

Google Calendar watch leases are a derived input adapter. A channel is reserved before registration; only a digest of its random callback nonce is stored. Each hint is fenced against the selected account/calendar revisions, callback address, resource identity, expiry and monotonic message number. An authenticated initial sync may precede the registration reply. Lost replies, duplicate hints and restart do not create calendar writes. Renewal uses a new channel, and removal/changed authority retires local acceptance before best-effort remote cleanup. The existing external observer is woken directly and performs provider readback; deterministic five-minute reconciliation remains the fallback. A reachable public HTTPS receiver is a deployment prerequisite, not an inferred account permission.

Runtime-issued coroutine-local telemetry attributes model invocations to an observation, work item or durable task. It is observational and never grants authority. Providers emit only role/model, measured wall time, outcome and optional reported token counts; prompts, responses, credentials and provider URLs are excluded. The persistence adapter owns additive migration 51. Missing usage stays unknown; demo invocations are excluded from real usage and no monetary price is invented. A shared extraction is displayed separately from direct work cost and counted only once in owner totals. Runtime invocations are not claimed to be HTTP attempts.

The owner-only versioned metrics API derives queue/room/work states, current processing latency, task resource usage, action timeline outcomes and review decisions. Older observations without completion timestamps do not become zero-latency samples. Unknown wrong-target or duplicate external effects remain unknown rather than inferred from a unique database key. A deterministic five-minute delay threshold uses a durable transition receipt and idempotent timeline publication; restart between detection and publication replays the same alert. Existing failed-processing and unknown-outcome handling remains authoritative. These source changes do not establish deployed monitoring or real push acceptance.
