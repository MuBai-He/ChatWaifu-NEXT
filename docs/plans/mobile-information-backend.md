# 手机信息收件箱与宁宁后端接入

手机独立采集微信并保存原文、待处理队列、已确认事项及提醒。默认的 AI 整理调用 ChatWaifu Runtime，复用后端的 memory_extraction 模型配置。模型供应商地址、模型名称和模型密钥由后端管理，手机保存的是服务器连接凭据。

## 本次接入边界

新增经过现有 Runtime Bearer 鉴权的两个接口：

- GET `/v1/personal-information/status`：返回 1.1 协议、整理能力是否就绪，以及客户端无需供应商密钥的标识。
- POST `/v1/personal-information/analyze`：验证主人会话、来源、输入预算和已有事项引用，使用后端 memory_extraction 路由产生待确认建议。

输入最多 30 段消息、16,000 UTF-16 单元的正文、20 个同会话事项和 6,000 字的前文。相对日期按原消息时间与显式时区解释。输出最多 12 项，限定来源引用、事项类型、版本和日期。

接口仅产生建议，不创建聊天回复、不执行 Runtime Skills、不自动写入长期记忆或日历。手机保留处理租约，并在建议与进度原子保存后推进队列。手机用户确认时保存本地事项；已有事项的修改检查版本，取消和完成撤销提醒。

## 客户端连接

手机默认显示“连接宁宁”。服务器地址和连接凭据与桌面连接属于同一个 Runtime，保存在 Android Keystore 加密的独立配置中。连接成功后建立主人会话，用于资料整理权限校验。手机无需复制后端模型供应商的 API Key。

之前的 OpenAI 兼容接口保留在高级选项“使用独立模型接口”，默认关闭。这个选项只供明确希望手机自行调用模型的情况使用。

## 验证与部署状态

在独立检出中新增接口与测试，原 CW2 工作目录的用户改动保留。18 项后端 HTTP 验证通过，覆盖鉴权、主人范围、源引用、输入预算、日期、目标版本和失败响应不泄漏私有内容。Ruff 和严格 Pyright 通过。

手机 0.4.0 的 18 项单元检查及 Debug/Release Lint 通过。真机的 52 项 SQLite 场景断言通过；手机到实际 Runtime 测试应用的接口验证通过，后端模型由合成适配器提供，覆盖日程、改期、完成、队列和人工确认。测试没有上传真实微信消息。

2026-10-12 已从实际线上源码构建并部署 `info-inbox-20261012-v1`，新增信息接口可用。Linux 84 项回归通过；真实模型与手机移动网络 HTTPS 验收通过，使用合成资料验证本人待办、截止时间、引用、入库及确认。保留原有配置、模型密钥、数据库及其他源码，重新核验并恢复此前启用的群路由。手机已复用原 Runtime 连接凭据，经 Keystore 加密保存；自动整理设置仍关闭。

## 后续同步

确认后的记忆与事项同步、服务器通知投递、设备配对凭据，以及宁宁对手机档案的检索仍需完整的后续切片。此接口接通的是后端整理调用，不能据此声称手机记忆已经进入宁宁长期记忆库。同步应复用现有记忆提案、策略和来源机制，明确权威记录及版本，避免把原文档案整体变成人格记忆。
