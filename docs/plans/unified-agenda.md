# 统一事项与提醒方案（待讨论）

日期：2026-09-28。状态：提案，未实现、未批准为新架构。
基线：PR #46，ADR 0057；用户已确认首次提醒、五分钟贪睡和重启恢复。

## 用户体验

个人助理以“今天／近期事项”为主入口，统一展示日程、待办和单独设置的提醒。
Google、Apple 不再各占一个业务页面，只在事项上显示来源；账号连接、日历选择、设备及权限放在设置。
按日程／待办／提醒筛选即可；闹钟是提醒的声音方式，不需要另建一套日程管理。

- “明天下午三点开会，提前十五分钟提醒”：一个原日历事件 + 一条引用它的提醒规则。
- “买牛奶，晚上提醒我”：一个原提醒事项 + 到期提醒，完成待办后取消未触发的提醒。
- “二十分钟后提醒我休息”：只创建一次提醒，无需写入 Google 或 Apple 日历。
- “每天八点叫我”：本地持久提醒规则，投递方式为响铃。
- 关闭通知仅处理本次提醒，不自动完成待办、删除日程或取消重复规则。

## 复用现有代码的分工

```text
文字 / 语音 / 事项界面
           ↓
个人助理查询与操作服务（主人作用域、权限、去重、结果状态）
     ├─ Google 日历适配器
     ├─ Apple EventKit 设备桥（日历 / 提醒事项）
     └─ 独立提醒规则（现有 SQLiteTaskRepository）
           ↓
到期实例 / 投递状态（现有服务器调度器）
           ↓
桌宠通知呈现 / 系统通知 / 响铃
```

统一的是事项视图、操作入口和提醒规则；Google / Apple 仍保存各自权威数据，不互相复制事项。
保留日程的起止时间、全天／重复语义与待办的完成状态，使用有类型的变体，不挤成一个万能字段表。
模型仍经过现有 Runtime Skill 权限，Google 写操作仍需单独实现和授权，不能因统一视图绕开只读权限。
Mac 只运行 EventKit 桥和提醒呈现；Linux 服务器负责已有 Google 接入与持久调度。
不复用 ambient 主动搭话的计时逻辑承载明确的用户任务，不新增第二个服务器调度器。

## 数据关联与同步

先加入统一的来源标识与能力描述，再让事项引用支持 provider / account / calendar-or-list / item-id / revision。
现有任务 ID、设备绑定、未处理投递和贪睡实例保留；兼容迁移增加可空的事项引用及提醒策略。
新增事项变动对账：事件改期更新提醒，取消事件或完成待办取消未来实例；保留历史结果。
外部源离线时显示缓存时间与未知状态，不推断条目被删除，不静默把失败写入改为本地事项。
联合操作分别报告“事项保存”和“提醒安排”的结果，避免半成功时笼统声称全部完成。

同一个 Google 账号可能也在 macOS Calendar 中暴露。优先选择一个权威访问路径（已直连的 Google），
通过可证明的账户／日历／原始条目标识或用户确认建立对应关系；不能按标题和时间盲目合并。
无法确定是否同源时明确显示来源，并允许关闭某个来源；不自动删除、合并或同步写入两边。

## 离线与无人操作（拟议）

把“允许迟到多久”“响铃多久”和“未处理卡片保留多久”拆开。
保留既有默认迟到窗口：闹钟两分钟、普通提醒一小时；是否调整为用户选项需讨论。

| 情况 | 提议行为 |
| --- | --- |
| 目标设备离线，重新上线仍在迟到窗口内 | 投递一次；通知说明实际到期时间 |
| 离线直到超过窗口 | 标记错过；下次上线显示安静的汇总，不突然补响 |
| 已展示，用户一直未处理 | 响铃达到上限后停止；收起为未处理记录，不能标成已完成 |
| 用户关闭 | 确认本次投递，保持事项与重复规则 |
| 用户贪睡 | 创建一个五分钟后的实例，保留原事项关联 |
| 提醒期间断网 | 保持本地可停止；记录待同步操作，上线重传确认而非重放事项写入 |
| 另一台设备在线 | 初期继续固定主设备，不自动迁移或多端同时响；显式切换设备需修订屏障 |

状态至少区分未送达／已展示／已处理／错过／未处理超时；保留终态原因。
一个通用通知收件箱显示最近的未处理／错过记录，当前分散的临时提示逐步复用同一呈现组件。
普通提醒只通知一次，不主动循环播报；闹钟默认最多响两分钟，不无限自动贪睡。
声音开始、停响上限和有效期需要独立时间字段，保留取消、离线与迟到输出的保护。
网页请求超时、通知送达、用户点选分别记状态，不能互相替代。

## 提醒卡片

卡片沿用桌宠配色和圆角：小图标／类型在上，事项标题突出，主操作关闭，次操作五分钟后提醒。
多条通知使用同一紧凑列表，长文本换行；系统错误在卡片内提供可恢复状态。
后续可在既有桌宠界面接入未处理入口，不因每个功能增加一个常驻浮动按钮。
PR #46 仅改卡片外观；新的收件箱和离线策略随下一阶段一起交付。

## 分步交付与讨论点

1. 收尾 #46 的已实现能力和用户验收，保留明确的未验收 Apple 写入边界。
2. 下一 PR 统一事项读视图、来源设置和公共通知呈现；复用已有 Google / Apple 查询。
3. 再接 Google 写入、事项与提醒关联，以及完成／改期的对账。
4. 独立落实无人处理与离线收件箱状态，再接云端实时语音的写操作及异步回执。

待讨论的产品选择：默认页面是否以“今天／近期事项”为中心；闹钟过期后只留安静记录是否符合期望；
普通提醒是否需要可选的轻提示音。现阶段建议前两项采用上述默认，普通提醒声音默认关闭。
