状态：实施中，尚未接账号或部署。日期：2026-09-22。
基线：`ceb9234`；参照 ADR 0022、0052、0053。本文不将任何阶段标为已完成。

阶段 A 当前进度：已实现独立 Google REST 适配器（`personal_assistant/google_calendar.py`），
包括授权码交换、刷新、撤销、日历分页、事件全量/增量批次和 410 受控重同步。
13 项供应商边界检查及 Ruff/Pyright 通过；这不是账号或桌宠验收。
适配器尚未注册到 Runtime，故当前产品仍不能查询日历。
事务仓储已落地（迁移 33、ADR 0055），包含主人作用域、默认不选择日历、修订号屏障、
原子事件/游标提交和撤销清理。7 项真实 SQLite 检查通过，原有数据库/迁移检查 14 通过、
1 项 Windows 专用检查在 macOS 跳过。
账号应用服务代码已实现：从持久会话派生主人作用域、保存离线只读授权、刷新后保存轮换令牌、
发现/选择/同步日历、本地优先撤销和可重试的远端撤销清理。独立秘密存储使用异步门面，
取消时先完成在途文件操作。仓储与账号边界合计 11 检查通过，适配器 13 检查通过。
这些服务已组装到 Runtime，可查询 disabled/unconfigured/ready/cleanup_failed 状态，
默认关闭。内部 OAuth 协调器已实现一次性 state、会话绑定、PKCE、期限、取消与退出清理。
仍没有授权 HTTP 提交入口、原生回调或用户可见日历功能，状态接口明确 authorization_available=false。
仓储/账号/OAuth 检查累计 13 项通过；状态接口 2 检查通过并正常退出。完整 Runtime 生命周期
检查断言通过但进程退出挂起，未改动基线也复现，不能记作完整通过。
下一步是原生 PKCE 回调、安全授权交接及控制中心 UI，
然后接入 Skill 权限和生命周期。Google 写入、Apple、持久提醒及语音扩展均待实现。

集成约束：同步批次只有最后一页成功才返回；仓储必须把事件与游标一起原子提交，
并校验账号修订以阻止撤销后迟到结果。410 后完整快照失败时不能把旧缓存标为最新。
账号服务的 `connect_authorized` 仅供后续完成 state/PKCE/期限与安全传输校验的授权协调器调用，
不得直接暴露成接受任意 token 的 HTTP 接口。启动时对专用秘密文件执行 reconcile，
清理无数据库引用的孤立凭据并重试已撤销账户的远端清理。文件与 SQLite 无跨存储事务，
因此取消创建后必须依据持久引用恢复，不能盲删已提交账号的令牌。
同步保留重复事件主记录与例外，不混入 `timeMin` 等增量 API 禁止的过滤参数；
时间段查询需单独实现有界的实例展开，不能只对主记录起止时间筛选。
刷新返回未携带 refresh token 或 scope 时应保留原值，不能抹掉已有凭据或擅自扩大授权。
令牌通过服务器秘密存储保存；适配器不承担账号授权、持久化和自动重试。
授权交接不能直接信任任意 `X-Forwarded-Proto` 或代理产生的回环 peer 地址。

## 1. 用户目标与范围

- 沿用用户现有 Google 日历和 Apple「提醒事项」列表，不创建新的日历产品，不要求迁移原有数据。
- 通过 ChatWaifu 文字和语音查询、创建、修改日程与待办，创建一次性和重复提醒，查看或取消已安排任务。
- 服务器常驻处理 Google 接入、同步、任务调度与投递。Mac 保持轻客户端，仅增加 Apple 系统能力桥接与通知播放。
- Home Assistant 纳入阶段 G，独立于日历与提醒；实现适配及设置界面，网络接入方式待用户提供，未经确认不改家庭路由或现有 VPN。
- 默认 reminder 指 Apple 提醒事项；Google Tasks 保留供应商适配位置，首轮不实施。首轮不做 iPhone App、手机时钟闹钟接管、任意脚本定时执行。

成功后的例子：

| 用户说 | 预期结果 |
| --- | --- |
| 明天下午三点到四点开会，加到工作日历 | 写入已选 Google 日历，返回事件与明确时间 |
| 把刚才的会议改到四点 | 定位已创建事件，处理并发修改后更新原事件 |
| 把买牛奶加到购物清单 | 写入已有 Apple 提醒事项列表，手机由 iCloud 同步 |
| 十分钟后提醒我关烤箱 | 服务器持久化一个提醒，并显示到期时间、提醒设备 |
| 每个工作日早上八点提醒我出门 | 创建重复提醒，可暂停、修改、取消和贪睡 |
| 今天有什么安排 | 聚合已授权的日历和待办，标出来源和同步状态 |

## 2. 当前基础与缺口

- Runtime 已有 Skill 注册、权限、确认、调用记录和取消机制；支持 MCP stdio/SSE/Streamable HTTP。
- 当前服务器实际上仅注册 `runtime.status`，没有配置外部 MCP 或插件。
- `companion/ambient.py` 负责空闲主动搭话，不承担明确时间的用户任务。
- 现有渠道投递调度器处理消息分段，不能直接改成通用定时任务调度器。
- 云端实时语音桥以 `require_cloud_readonly=True` 执行工具，写操作和持久任务必须扩展完整交互路径。
- 当前远程客户端没有服务器调用 Mac 系统能力的设备注册、命令与回执通道。
- 参与者只表示对话身份。首轮仅主人私聊可使用个人账户；访客、共享场景不继承日历、提醒列表或任务权限。

## 3. 架构决定

### 原有服务保持权威数据

Google 保存日历事件；Apple EventKit/iCloud 保存提醒事项。ChatWaifu 仅缓存查询需要的字段、外部 ID、同步版本与更新时间，不把缓存变成另一套可独立编辑的日历。

ChatWaifu 自有数据限于账号连接元数据、操作记录、设备命令、定时计划及送达记录。日程不自动写入长期人格记忆。两家服务之间不自动互相复制事项。

### 通过现有 Skill 入口调用有类型的服务

调用方向：对话/语音 → Skill Router → 权限与操作网关 → 日历、待办或调度服务 → Google/Apple/通知适配器。

首轮优先官方 Google API 和 EventKit，不依赖第三方 MCP 承担同步或长期调度。MCP 后续可作为适配器来源，但不能替代数据库中的任务状态。安装在 Codex 中的工具不会自动成为 ChatWaifu 能力。

拟新增 `personal_assistant/` 应用服务、供应商适配器及 persistence 仓储；协议归入现有协议包，具体命名在实现前的 Proposed ADR 中固定。供应商 SDK 类型不穿过适配器边界，业务服务不直接访问 SQLite。

### 四类持久记录分开

| 记录 | 作用 |
| --- | --- |
| ExternalItemReference | 关联账户、日历/列表、外部条目、版本和缓存新鲜度 |
| ActionOperation | 记录一次查询/写入的请求 ID、目标、结果、冲突或未知结果 |
| ScheduledTask / Occurrence | 保存执行内容、时区、规则、修订及每次应执行时间 |
| Delivery / DeviceCommand | 跟踪具体设备的领取、确认、投递、取消与超时 |

所有记录带服务端派生的 owner/scope；定时任务独立于短命的聊天 session 和 generation。`request_id`、任务修订、执行批次与外部 ID 用于去重，不许承诺跨供应商的绝对 exactly-once。

## 4. Google 日历

1. 用户连接自己的 Google 账号，选择允许读取的日历与默认写入日历，读取日历权限，禁用只读日历的写操作。
2. 首版提供查询时间段、创建、修改、删除事件；覆盖时区、全天事项、持续时间和重复事件的识别。对已有复杂重复事件，明确只改本次还是整个系列；未支持的操作明确拒绝，不摊平成普通事件。
3. 首版不自动邀请外部联系人或发送会议邀请；保留供应商字段，编辑无关字段时不能覆盖它们。
4. 首轮用增量轮询同步，避免依赖公网 Webhook。按 API 要求固定同步参数，分页完成后才提交 sync token；410 触发受控重同步，不能把远端条目重复导入。
5. 更新/删除携带 ETag 条件，冲突重新读取并展示差异。创建使用可重试的稳定标识；网络结果不明时先查询核对，再决定是否重试。
6. 写入成功后直接读回并更新缓存；定时刷新获取用户在 Google 侧的修改。显示最后同步时间、授权失效和离线状态。

授权路线：Mac 开发阶段采用 Google Desktop OAuth 客户端、系统浏览器、PKCE 和临时 loopback 回调。原生宿主只处理短期授权交接，长期凭据由服务器保存；授权交接绑定登录的 Runtime、state、一次性请求和有效期。实际账号接入前先解决客户端到服务器的受保护传输，不能在当前裸 HTTP LAN 通道上传长期账号凭据。未来纯 Web 客户端采用合规 HTTPS 回调。实现第一阶段先验证这条授权链路，不要求用户粘贴密码到聊天。

Google OAuth 凭据与刷新令牌放服务器独立秘密存储，API 只展示脱敏状态；撤销连接立即停止同步及关联操作。不得在日志、模型上下文、前端长期存储或任务参数中写入令牌。

## 5. Apple 提醒事项与 Mac 桥接

- 在 Tauri 宿主中增加小型 Swift/EventKit 适配，不在 Mac 启动 Python Runtime 或模型服务。
- 用户授权后选择已有列表，支持读取、创建、修改、完成、删除；首轮保留原条目未涉及字段。复杂子任务、标签、附件、共享分配和特殊重复规则不假装完整支持，以实际 EventKit 能力为准。
- Mac 主动连接服务器：注册 device_id、声明能力、领取绑定自身的结构化命令、返回结果。不用暴露 Mac 入站端口，也不提供任意 shell 执行。
- 设备单独配对、可撤销；仅接收已授权账户/列表/操作，命令带有效期、操作 ID 和修订。账号撤销或列表权限改变后拒绝旧命令。
- 默认指定一台 Mac 为该提醒账户的写入设备，避免多台设备各建一次。原生端保留轻量操作日志；创建返回前后发生断线时核对原记录，无法确认则标为“结果待核实”，不能盲目重建。
- EventKit 变化通知触发有界重新读取，应用启动和重连也核对。外部 ID 变化或记录消失时重新关联，不能把一次暂时不可见直接认定为用户删除。
- 完成层级区分“服务器已接收”“等待 Mac”“已写入 Mac 提醒事项”；后者不等于已经在所有 iCloud 设备可见。
- Mac 休眠、关机或桥接未运行时，新请求排队或过期。界面显示设备离线和缓存时间；撤销待执行请求会持久化取消状态。退出桌宠即停止桥接是首版默认行为，独立常驻 helper 后续再评估。

## 6. 服务器定时任务

首版动作仅限提醒通知/播报，以及已授权的日历、待办操作。禁止保存任意模型指令并在到期时无边界执行。

- 创建时先持久化，再回复“已安排”；保存 UTC 执行时间、原始 IANA 时区、重复规则、目标设备、允许的操作和错过执行策略。
- “十分钟后”按确定时间点调度；“每天八点”按保存的时区计算，夏令时跳时/重复时有明确规则，单次执行不重复触发。歧义日期或缺失重要目标时才追问。
- 状态区分等待执行、执行中、完成、失败、取消、等待设备、结果待核实；重复计划的某次失败不等于整条计划结束。
- 复用 SQLite WAL，采用事务领取、有限租约、心跳和修订 fencing；任务扫描由最近到期时间和变更唤醒驱动，单任务不永久占用协程。
- 网络请求超时且结果未知时，先核对供应商结果；只对可安全重试的动作退避重试。重启恢复未完成记录，使用 occurrence ID 防止重复提醒。
- 每次执行重新检查账号、权限、任务修订和有效期；计划创建不授予永久权限。个人任务首版不受普通闲聊 quiet-hours 或主动频率预算误拦截。
- 提醒错过时间后，按预设窗口合并补发并标“已错过”；陈旧闹钟不突然响铃。窗口作为明确设置保存，不把所有过期动作自动重放。
- 修改和取消增加修订并使旧执行失效。取消聊天生成不自动取消已成功建立的日程或定时计划；外部写入已提交时不承诺回滚，撤销是单独操作。

## 7. 提醒、闹钟与送达

先交付运行中桌宠的提醒：通知卡片、系统通知、可选角色 TTS，操作包括查看、停止、完成、稍后提醒。

- 同一 occurrence 只选一个主播报设备，其他设备可显示未读状态；提醒事项与 Google 已有系统通知默认保留，额外角色播报需启用，避免不知情的重复提醒。
- 通知和 TTS 发送、客户端收到、系统通知提交、播放结束、用户确认分别记录。“播放结束”不能写成“用户听见”。
- 普通提醒在正在通话时可先显示卡片；是否播报和是否打断依用户设置。响铃无需等待 LLM 回答，TTS 不可用时用本地提示音。
- 闹钟首版覆盖运行中且联网的桌宠，提供重复响铃、停止和贪睡。服务器仍调度任务，但不能让关机/深度休眠的笔记本发声。
- 若以后要求桌宠完全退出后仍响铃，再增加系统常驻通知 helper/本地预排与修订同步。手机原生闹钟需独立 iOS 端能力，不在首版中承诺。
- 设置默认目标设备，设备全部离线时显示等待或错过。微信/其他渠道可作为用户选定的备用投递，须单独验收，不以现有渠道存在就宣称已实现。

## 8. 对话、语音与 UI

在现有控制中心加入“个人助理”入口，含账号连接、今日事项、定时任务、提醒设备。每一阶段随功能交付对应 UI，不最后堆一个管理页，不添加桌宠浮动按钮。列表保留来源标识及可用的原应用入口。

工具声明建议按 `calendar.*`、`reminders.*`、`schedule.*` 提供明确 schema。所有操作经现有权限网关，只投影当前问题需要的工具。

用户明确要求创建/修改且目标、时间清楚时，允许在已授权能力范围执行，不每次重复确认。删除整组、邀请他人或有歧义的操作再确认；安装、账户授权与单次操作确认分开。

先接文字与现有 Cascade 对话路径，再扩展 Cloud Realtime：支持具体受限写工具、待确认与等待设备状态、结构化执行回执、打断后的提交边界和 P13.6 上下文刷新。不能仅移除 `require_cloud_readonly`。等待设备不占住一次长语音工具调用，返回任务 ID 后由独立结果通知呈现。

外部结果进云端模型仍经过现有外发策略；查询个人日程不能把整个账户内容注入每次聊天。共享场景默认隐藏个人内容，只有主人私聊可执行本轮能力。

## 9. 分阶段交付

| 阶段 / PR 边界 | 完整交付 | 实机验收 |
| --- | --- | --- |
| A：Google 只读连接 | 最小账户/操作协议、授权、日历选择、查询与同步、账号 UI | 读到已有事件；Google 侧修改后能同步；断开授权立即失效 |
| B：Google 写入 | 有权限的创建/修改/删除、冲突与去重、文字/Cascade 操作 | 创建事件后在原日历可见；往返编辑；断线重试不重复建事件 |
| C：持久提醒 | 调度仓储、一次性/工作日重复、运行中桌宠投递、任务 UI | 两分钟提醒；重启恢复；取消不触发；离线状态明确 |
| D：Apple 提醒事项 | Mac 配对与命令通道、EventKit、指定列表与同步 UI | 创建与完成出现在原列表；iPhone 同步观察；Mac 离线排队后不重复 |
| E：闹钟与联合操作 | 停止/贪睡、主设备选择、提醒目标设置；关联日程/待办 | 停止和贪睡生效；双客户端只响主设备；分别报告多步骤成败 |
| F：云端实时语音 | 写工具准入、确认交互、异步结果、取消边界、上下文同步 | 通话中创建真实日程/提醒；打断不重做；设备延迟不会卡死通话 |

阶段按 A → B → C → D → E → F 推进；不先搭一整套通用框架再接首个可用场景。Google Tasks、复杂 Apple 条目、手机端留作后续独立阶段；HA 按下述阶段 G 推进，可与个人账户接入独立验收。

## 10. 验收与实施纪律

- 此轮只交付方案，不接账号、不触发真实提醒、不修改部署、不新增测试脚本。
- 实施时优先扩展已有检查，只补能发现真实故障的边界：作用域越权、同步冲突、重复执行、重启领取、取消竞态、设备离线、语音迟到结果。
- 每个阶段在当前桌宠和常驻服务器验证一条真实完整链路；有 UI 改动则构建并实际检查关闭、返回、失败和重连。禁止用 mocks/HTTP 200 代替原应用里的实际结果。
- 先写 Proposed ADR 固定账户主权、设备命令和调度责任；数据库迁移沿用当前迁移序列，不预占版本号。功能默认关闭，迁移不修改现有日历/提醒。
- 关闭功能停止新调度与账号同步，保留已产生外部事项；撤销账户和删除任务是独立操作。发布说明区分源码 Mac 验收、安装包、Windows/Web 和手机端能力。

开工前仅需在相关阶段确认：Google 账号及默认日历、Apple 默认列表、提醒主设备。规划默认时区 Asia/Shanghai，写入和显示时均允许用户更改。

## 12. 阶段 G：Home Assistant

- 先采用 HA 官方 MCP Server，读取已暴露的设备，再支持灯、开关、空调和窗帘的日常操作；日历和待办仍使用 Google/Apple，不改由 HA 承载。
- ChatWaifu 服务器直接访问 HA 的 `/api/mcp`。目前 Mac 能 SSH 到 HA，但服务器访问 `192.168.10.216:8123` 超时；需要用户提供服务器可达地址/现成 VPN，或明确选定网络方案。不可把 Mac 临时转发当成常驻最终方案。
- MCP 的私网访问改为操作员配置的精确主机/端口允许列表，连接配置本身不能扩权；保持 DNS 解析固定、禁止跨源重定向、拒绝 metadata/link-local 地址。已有公网/回环策略维持兼容。
- 通过 HA 官方界面添加 MCP Server 集成、选择暴露设备和专用凭据；凭据存于服务器秘密存储。调试不批量操控设备，先查状态，再对用户选定的一盏灯验证操作及回读。
- 将可用设备按区域/名称给模型检索，不在每次对话塞入全屋实体。设备变化后的能力刷新、失联和权限撤销必须可见。
- 先沿用当前 MCP 的确认机制；后续给已选设备的日常操作提供受限授权，不能简单对整个 MCP 连接关闭所有确认。修改 HA 配置、删除自动化等管理能力不进入默认日常工具集。
- 社区 ha-mcp 与其 Skills 在需要创建自动化时单独评估，不为了开灯安装完整管理工具集。
- 验收：从常驻服务器发现工具、主人私聊查询和操作已选设备、实体回读、撤销授权后失效；访客/共享场景不可调用。真实设备结果由用户确认。

## 13. 用户协助清单与无人值守边界

睡前若方便，只需提供已有 Google OAuth 客户端配置文件路径，以及 HA 的可达地址/已有 VPN 情况；没有现成配置也可明确告知。不要把密码、访问令牌或密钥贴进对话。

后续必须由用户完成的步骤：

1. Google 登录授权及选择现有日历；如无 OAuth 项目，完成自己账号下的项目/客户端创建和同意屏幕配置。
2. 在 Mac 的系统弹窗允许访问 Apple 提醒事项，并选择已有列表。
3. 确认 HA 接入网络方案和用于真实控制验收的设备。
4. 选择默认提醒设备并确认真实声音效果。

开发期间可以自主完成代码、相关现有检查、文档和独立 PR；保留账号未接入/设备未授权的真实状态。未得到授权不能绕过系统弹窗、获取浏览器登录凭据、猜测私有网络配置，或宣称外部账号和物理设备已验收。
